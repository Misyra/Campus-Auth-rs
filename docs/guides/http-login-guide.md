# 直连请求登录使用指南

> 本文对应当前实现：直连的请求参数落盘在 `<base>/tasks/http/<id>.json`（请求由 `src/login/http_login.rs` 发出），界面为侧栏「任务 → 直连任务」子页（任务编辑器与其中的「配置向导」）与「方案」页「登录方式」区域的「直连任务」下拉。
> 面向使用者；字段级契约与判定细节均以源码为准，本文只描述用户可见行为。

## 1. 它解决什么问题

校园网登录有三种执行方式，在「方案」页的方案编辑器里、**登录方式**区域切换：

| 登录方式 | 怎么工作 | 适合 |
|----------|----------|------|
| 浏览器自动化 | 拉起 Python Worker 与 Playwright，按浏览器任务的步骤操作登录页 | 有验证码、动态表单、复杂交互的门户 |
| **直连请求** | 在程序进程内按「直连任务」里的请求参数直接向网关发一次 HTTP 请求完成登录 | 门户登录接口可以直接调用，且不需要验证码 |
| 自定义脚本 | 在程序进程内起子进程跑「登录脚本」，凭据经环境变量交给脚本，退出码 0 即本次成功 | 请求要按门户逻辑加密/签名、要多步取参，又不值得上浏览器（见[自定义脚本指南](custom-script-guide.md)） |

直连与自定义脚本都**不需要** Python 环境与浏览器（脚本只用到子进程与你自己指定的解释器），也都**不会**自动切回浏览器。

直连请求的实际收益：

- **不需要 Python、Playwright 与浏览器**：整个登录在程序自身进程内完成，环境缺失不影响它。仪表盘也不会因为 Python 环境未就绪而提示你。
- **更快、更省资源**：不启动浏览器，单次登录通常几十毫秒到几百毫秒。
- **不回落浏览器**：直连失败按普通登录策略重试（默认最多重试 3 次，间隔 5 秒并逐次翻倍，即 5 → 10 → 20 秒），**不会**自动改用浏览器。要用浏览器请手动切换登录方式。

### 1.1 参数放在哪：独立的「直连任务」

直连的请求参数**不属于方案**，而是独立的**直连任务**：

- 直连任务在侧栏「任务 → 直连任务」子页（地址 `/tasks/http`）里新建、编辑、复制、导入导出，与「浏览器任务」「脚本」「定时任务」「AI 生成浏览器任务」并列；参数落盘在 `<base>/tasks/http/<id>.json`。任务有自己的名称与描述，请求参数按填写顺序分六组（见第 3 节；第 4、5、6 组是可选的高级项）。
- **同一个直连任务可被多个方案复用**：同一个门户的不同账号共用一份请求配置，不必每个账号抄一遍——这正是它从方案里独立出来的全部意义。
- **账号、密码仍属于方案**；**认证地址**两者都有：任务的认证地址优先，任务里留空则回退用方案的认证地址（两个渠道共用同一个地址设置）。

在方案侧，方案编辑器的「登录方式」区域选「直连请求」后会显示一个**「直连任务」下拉**（首项是「未绑定（直连登录不可用）」，可随时把任务摘下来）；旁边是「发送测试请求」（用方案的账号密码发一次，不保存、不改变自动登录状态）与一个「配置直连任务」入口（跳转到任务页并打开所绑定的那个任务）。

> **直连没有内置任务**：浏览器渠道有内置的「通用登录」任务可回退，直连**没有**——门户地址因人而异，无法内置。因此**未绑定直连任务时直连登录会直接失败**：方案编辑器会当场提示，保存方案时也会拒绝「选了直连但没绑任务」的组合。

## 2. 开始之前：确认你的门户适合直连

直连请求要求门户的登录动作是**一次可以直接构造的 HTTP 请求**。判断方法：

1. 打开校园网登录页，按 <kbd>F12</kbd> 打开开发者工具，切到 **Network / 网络** 面板。
2. 勾选 **Preserve log / 保留日志**（否则跳转后请求记录会被清空）。
3. 故意输入**错误的密码**并点登录。
4. 在请求列表里找提交账号密码的那一条（地址常含 `login`、`portal`、`eportal`、`drcom` 等字样），看它的：
   - **Request Method**：GET 还是 POST
   - **Request URL**：完整地址与查询串
   - **Form Data / 表单数据**（POST）：字段名与值
   - **Request Headers**：是否有 `Referer`、`Content-Type` 等必要头

如果在登录前还有一个**图形验证码需要人工识别**，直连请求无法完成（它不会做 OCR），请继续使用浏览器自动化。如果门户把密码加密后再发送（表单里的密码是一串十六进制或 Base64），直连请求**仍然可以**做到——见第 6 节。

> 程序内置了分步向导，与本文内容一致：在**直连任务编辑器**里（「任务」页 → 直连任务 → 新建或编辑任务 → 右上角「配置向导」）点开它，会带着你走完同样的四步——确认任务与认证地址 → 照抄门户登录请求 → 设定成败判定 → 发送测试（当场发一次真实请求）。向导改的就是当前这个任务，改动与编辑器同步并**照常自动保存**；最后一步的测试用的就是向导里填进去的内容。

## 3. 六组请求参数（都在直连任务编辑器里）

在侧栏「任务 → 直连任务」里新建或编辑一个任务，参数共六组，顺序即填写顺序（第 4、5、6 组默认收起，用不到就留空）。

### 3.1 方法与请求地址

- **方法**：照抄开发者工具里的 Request Method。
- **请求地址**：完整地址。把地址里出现的账号、密码替换为占位符（下一节）。
- **认证地址**：门户登录页的地址，**可以留空**。留空时运行时回退用方案的认证地址，自己用照旧工作；**要把任务分享给别人就填进来**——否则对方导入后还得自己摸出认证页地址。

### 3.2 请求头

每行一项，格式为 `名称: 值`。空行与不含冒号的行会被忽略。

- POST 且填了请求内容时，如果没写 `Content-Type`，程序会自动补 `application/x-www-form-urlencoded`。
- 部分门户校验 `Referer`，此时需要照抄浏览器的值：`Referer: {auth_url}`。
- 没写 `User-Agent` 时程序会补一个浏览器 UA（多数门户需要它才正常响应）；要伪装成别的 UA，就在请求头里显式写一行 `User-Agent: ...` 覆盖。

### 3.2.1 HTTPS 证书（仅 https 门户需要关注）

「HTTPS 证书」默认是**跟随全局设置**，即跟随「设置 · 浏览器」里的「忽略 HTTPS 证书错误」（默认忽略）——校园网门户大量使用自签名证书，与浏览器自动化保持同一口径才能用直连登进去。三个选项：

| 选项 | 行为 | 什么时候选 |
|------|------|-----------|
| 跟随全局设置（默认） | 用「设置 · 浏览器」的证书开关 | 一般不用改 |
| 忽略证书错误 | 无论证书是否有效都不校验 | 门户证书异常（自签名、过期、域名不符）而全局设成了严格校验时 |
| 严格校验证书 | 证书不可信即直接失败 | 门户证书正常、且你希望降低凭据被中间人截获的风险 |

选**严格校验证书**后，自签名门户会直接报证书错误、登录失败——这是预期行为，不是程序故障。

### 3.3 请求内容（POST）

照抄 Form Data 的字段名，把值换成占位符，例如 `username={username}&password={password}`。

### 3.4 成功与失败关键字

程序**先看失败关键字，再看成功关键字**：

| 情况 | 判定 |
|------|------|
| 响应内容含**失败关键字** | 判定凭据被拒绝（终态失败，**不重试**） |
| 未命中失败关键字，响应内容含**成功关键字** | 判定成功 |
| 未命中失败关键字，**成功关键字留空** | HTTP 2xx 即判定成功 |
| 都不命中 | 判定「未命中成功标识」，按可重试失败处理 |

**关键提醒**：一部分门户（Dr.COM / eportal 这类 JSONP 接口最常见）无论登录成功还是密码错误，**都返回 `HTTP 200`**。这类门户如果留空成功关键字，密码输错也会被判成登录成功，然后被登录后的网络探测纠回来——表现为「明明登录成功了却一直是离线」。务必按下一节的方法把两个关键字都填上。

**判定方式还可以换成「网络检测」**（编辑器第 3 步的「判定方式」下拉）：响应内容完全不可靠、或成功标识实在难以确定的门户适用。这种方式下，登录请求发出后**不再看响应内容**（失败关键字仍生效，门户明确报错时立即判失败），稍等片刻做一次公网连通探测，**能上外网才算登录成功**，未通过按可重试失败处理。程序本来就会在判定成功后做一次网络探测兜底（防止"响应说成功但实际没登上"），网络检测模式只是把这个兜底从第二道关提升为唯一判据。

### 3.5 前置请求（可选：先取令牌再登录的门户）

有些门户的登录请求必须带一个**先从别的接口取回的令牌**，典型是 CSRF token；更麻烦的是这个令牌**绑定 TCP 连接**——取令牌与提交登录如果不在同一条连接上，门户会直接拒绝（如返回 `400 {"error":"CSRF token mismatch"}`）。这类门户以前只能靠浏览器方式（浏览器加载页面与 AJAX 天然共用一条连接），现在可以用「前置请求」在直连渠道表达。

第 5 组字段（默认收起，**请求地址留空即整块忽略**）：

| 字段 | 说明 | 例 |
|------|------|----|
| 方法 / 请求地址 | 取令牌的那个接口 | `GET http://10.100.51.1/api/csrf-token` |
| 取值方式 | 只支持 JSON 路径：`json:<字段>[.<字段>...]` | `json:csrf_token`、`json:data.token` |
| 占位符名 | 取到的值注册成什么占位符；留空则用字段名 | `csrf` |
| 请求头 / 请求内容 | 取令牌那一次请求要带的头与体（多数门户留空即可） | `X-Requested-With: XMLHttpRequest` |

取到的值在**登录请求**里用 `{占位符名}` 引用，例如请求头里写一行 `X-CSRF-Token: {csrf}`。前置请求自己也能用 `{username}` / `{isp}` / `{auth_url}` / `{local_ip}` 这些占位符（见第 4 节）。

几条要点：

- **两次请求由同一个连接池顺序发出**，因此令牌绑连接的门户能通过；程序不做并发、也不对前置请求重试。
- **响应被 JSONP 包裹也能取到**（如 `dr1003({"csrf_token":"..."})`），前后夹带脏字符同样能取。
- **取不到值就不发登录请求**：直接终态失败，并把这一次前置请求的地址与响应带进结果面板——是取令牌的接口不对，还是登录接口不对，一眼能分清。
- 取到的令牌与账号密码同等对待：日志、登录历史与结果面板里都是 `***`。
- 令牌写在 HTML 里的门户不必用这一组：「凭据变换脚本」读登录页原文（`ctx.page`）更直接（见第 6 节）。

### 3.6 退出登录请求（可选：门户嫌你"还在线"时用）

有些门户在旧会话仍存在时会拒绝再次登录（提示「IP 已在线」「请勿重复登录」，或直接返回一个 already-online 类错误）。它们通常还提供一个**下线接口**：填上这一组，程序会在登录**之前**先请求一次，把旧会话踢掉。

- **请求地址**：门户的下线接口地址。留空 = 整块忽略（默认收起状态就是这样）。
- **方法 / 请求头 / 请求内容 / 下线后等待**：与登录请求同一套写法；下线通常是异步生效的，门户慢就设 1~3 秒的等待（0~30 秒）。
- **占位符**：只能用第 4 节里**内置**的那几个（`{username}` / `{password}` / `{isp}` / `{auth_url}` / `{local_ip}` / `{local_mac}`）。这一组排在凭据变换脚本**之前**，脚本产出的字段此时还不存在。
- **它排在最前面是有原因的**：旧会话还在时，这类门户的登录页会被重定向到「已在线」页——脚本据此算出来的字段全是错的。先清场、再读登录页与算字段，因果顺序才对。也因此，"下线后等待"期间不会有任何其它请求发出。
- **成败不影响登录**：下线是"触达即可"的动作——门户没开这个接口、地址写错、网络失败，都只记一条日志，登录照常进行并按自己的成功/失败关键字判定。所以配错了也不会把能登上的门户弄成登不上。
- 与「前置请求」的区别：前置请求是**取值**（取不到就不发登录请求、直接失败），退出登录请求是**动作**（不判结果）。

## 4. 占位符

请求地址、请求头、请求内容里都可以写占位符，发送前会被替换成真实值：

| 占位符 | 含义 | 替换后的值示例 |
|--------|------|----------------|
| `{username}` | 当前方案的账号 | `20230001` |
| `{password}` | 当前方案的密码（**原样替换、不做转义**） | `secret123` |
| `{isp}` | 当前方案的运营商字段原样透传（预设「移动/联通/电信」或自定义关键字，未选择为空串）；门户侧写法（如 Dr.COM 的 `@cmcc` 后缀）由脚本映射 | `移动` |
| `{auth_url}` | 本任务的认证地址；任务里留空时为方案的认证地址 | `http://10.10.1.1/srun_portal_pc` |
| `{local_ip}` | 本机主用网络接口的 IPv4（取不到时为空串） | `192.168.123.210` |
| `{local_mac}` | 同接口的 MAC，**固定小写冒号分隔**（取不到时为空串） | `bc:38:98:39:ce:34` |
| `{任意脚本字段}` | 凭据变换脚本返回的字段，见第 6 节 | — |

> **关于 `{local_mac}` 的格式**：程序统一输出 `aa:bb:cc:dd:ee:ff`（小写 + 冒号分隔，与 Linux `ip link` 一致）。很多门户要求的是**不带冒号**的形态（如 Dr.COM 常见的 12 位裸十六进制 `bc389839ce34`，或大写 `BC:38:…`），直接引用会提交错误格式——这是 MAC 类字段最常见的误判来源。请按门户实际要求在脚本里转换后引用：
>
> ```javascript
> function transform(ctx) {
>   return {
>     mac_plain: ctx.local_mac.replace(/:/g, ""),        // bc389839ce34
>     mac_upper: ctx.local_mac.toUpperCase(),             // BC:38:98:39:CE:34
>     mac_dash: ctx.local_mac.toUpperCase().replace(/:/g, "-"), // BC-38-…（Windows ipconfig 原文形态）
>   };
> }
> ```
>
> 另注：eportal / Dr.COM 一类门户实际靠**来源 IP** 防串号，`wlan_user_mac` 提交空值即可，多数场景用不到 MAC。

两点务必注意：

1. **值原样替换，不做 URL 编码**。账号或密码含 `@`、`&`、`+`、空格、中文等特殊字符时，直接拼进地址会破坏请求。这类门户需要在脚本里用 `url_encode()` 处理后再引用。
2. **写错的占位符会原样发出去**（这是有意设计，便于在测试结果里发现拼写问题）。测试结果会显示实际发出的请求，请核对其中没有残留 `{` 字符。

## 5. 发送测试请求

有两个入口，用途不同：

- **直连任务编辑器里**（「任务」页 → 直连任务 → 新建/编辑任务）：任务本身不含凭据（账号密码属于方案），所以测试时要手填一次**「测试账号 / 测试密码」**，再点「发送测试请求」当场发一次真实请求。用的是编辑器里的**当前内容**（改动已自动保存，见头部状态字）。
- **方案编辑器「登录方式」区域**：选中「直连任务」后点「发送测试请求」，用**方案的账号密码**发一次，不用手填凭据；已保存的方案可以留空密码，程序会回退本机已保存的凭据。

两者的共同点：只发请求，**不保存任何配置**，也不改变自动登录状态；同一时刻只允许一个测试在进行，重复点击会被拒绝。

结果面板给出的结论：

| 结论 | 含义 | 该怎么处理 |
|------|------|-----------|
| 请求判定成功 | 请求已按配置判定为成功 | 到方案里绑定这个任务并保存方案 |
| 门户拒绝凭据 | 响应命中失败关键字 | 确认账号密码；若需加密请写脚本 |
| 未命中成功标识 | 请求送达但没找到成功关键字 | 核对成功关键字是否与真实响应一致 |
| 请求未送达 | 连接失败 / 超时 / 证书校验失败 | 确认已连校园网、地址本机可达；证书问题见第 9 节的 HTTPS 证书说明 |
| 配置或脚本错误 | 请求根本没发出 | 看面板里的「脚本错误」具体原因 |

展开**查看实际发出的请求与响应**可以对照排查：请求地址/请求头/请求内容/响应头/响应片段都会显示，其中的账号、密码以及脚本产出的值均已替换为 `***`。响应头（含 `Content-Type` 里声明的 charset）是排查「中文乱码导致关键字命中不了」的关键线索。

## 6. 门户要求密码加密：凭据变换脚本

如果门户提交的不是明文密码，可以写一段脚本把明文变换成门户要求的形态。这一组在任务编辑器里**默认收起**，可选。

**契约**：脚本需定义 `function transform(ctx)`，返回一个对象；返回对象里的字符串、数字、布尔字段都会成为可被 `{字段名}` 引用的占位符（与内置占位符同名时会覆盖内置值）。

`ctx` 可读入参：

| 字段 | 含义 |
|------|------|
| `ctx.username` / `ctx.password` | 明文账号与密码 |
| `ctx.auth_url` | 本任务的认证地址；任务里留空时为方案的认证地址 |
| `ctx.page` | 认证地址页面的 HTML 原文（抓取失败时为空串） |
| `ctx.local_ip` / `ctx.local_mac` | 本机主用接口地址（取不到时为空串） |

可用内置函数（均为纯计算，**没有网络与文件访问能力**）：

`md5(text)`、`sha1(text)`、`sha256(text)`、`hmac_sha256(key, data)`、`base64_encode(text)`、`base64_decode(text)`、`hex_encode(text)`、`url_encode(text)`、`now_ms()`

沙箱限制：递归深度 64、单次循环最多 10 万次、**脚本执行上限 500 毫秒**，超时即判定为配置错误（终态失败，不重试）。

最小示例（门户要求 MD5 密码）：

```javascript
function transform(ctx) {
  return { password: md5(ctx.password) };
}
```

使用时把请求内容写成 `username={username}&password={password}` —— 脚本返回的 `password` 已覆盖内置值。

### 6.1 需要按本机 IP 推导密钥的门户

eportal / Dr.COM 一类门户的字段加密密钥由**客户端来源 IP** 推导，此时用 `ctx.local_ip`：

```javascript
// 密钥 = 来源 IP 各字符 ASCII 的 XOR 累积；每个字段逐字符 ^key 后转两位十六进制
function keyOf(ip) {
  let k = 0;
  for (let i = 0; i < ip.length; i++) k ^= ip.charCodeAt(i);
  return k;
}

function enc(s, k) {
  let out = "";
  for (let i = 0; i < s.length; i++) {
    const h = (s.charCodeAt(i) ^ k).toString(16);
    out += h.length === 1 ? "0" + h : h;
  }
  return out;
}

function transform(ctx) {
  const k = keyOf(ctx.local_ip);          // 取不到时为空串 → k 为 0，须按门户实际行为处理
  return {
    account_enc: enc(",0," + ctx.username + "@cmcc", k),
    password_enc: enc(ctx.password, k),
    ip_enc: enc(ctx.local_ip, k),
  };
}
```

> `ctx.local_ip` 取的是**本机主用网络接口**的地址，不是回环地址。多网卡机器（有线 + 无线 + 虚拟网卡）时程序按「有网关 → 非 Wi-Fi → 列表首个」选择，以尽量与 TCP 源地址一致。取不到时为空串，脚本必须能容忍，否则会算出错误的密钥。

### 6.2 加密结果含 Base64 / URL 特殊字符时的编码

若门户把加密结果转成 Base64（含 `+ / =` 等字符）再放进 **GET 查询串**，必须先用 `url_encode()` 处理，否则 `+` 会被服务端解析成空格、解密必然失败：

```javascript
function enc(s, k) {
  let out = "";
  for (let i = 0; i < s.length; i++) {
    out += String.fromCharCode((s.charCodeAt(i) ^ k) & 0xFF);
  }
  return url_encode(base64_encode(out));   // 先 Base64 再 URL 编码
}
```

hex 输出（只有 `0-9a-f`）没有这个问题，直接拼即可。另外：脚本里做 32 位散列/乘法运算时请用 `Math.imul(a, b)`，不要写 `a * b`——JS 的 `Number` 乘法在超出 2^53 时会丢失低位，`(h * 0x01000193) >>> 0` 与真实 32 位溢出乘法结果不同，算出的密钥会与门户不一致且无任何报错。

## 7. 保存并启用

两处保存，缺一不可：

1. **任务落盘**：直连任务编辑页里**改动自动保存**（停手半秒落盘到 `<base>/tasks/http/<id>.json`），没有保存按钮；头部状态字显示「已保存 · 刚刚」。若地址等必填项还没补齐，状态字会改口「有 N 处待补全，改动暂未保存」，按提示补完即自动落盘。
2. **绑定并保存方案**：回到「方案」页，在方案编辑器的「登录方式」区域选「直连请求」，从「直连任务」下拉里选中它，再点「保存方案」。账号、密码、认证地址与这个绑定关系同在方案编辑器里，一次保存一起落盘。方案编辑器仍是**显式保存**——方案里有凭据，改动不点保存不生效。

「选了直连但没绑任务」的组合在保存时会被拒绝并提示——直连没有可回退的内置任务。

保存后自动登录就会走直连。想确认实际执行的是哪条渠道，可以看仪表盘的**实时日志**：直连的失败消息形如「直连请求失败: …」，成功消息形如「登录成功（直连请求成功（HTTP 200 OK））」，而浏览器渠道的记录里是「步骤 N/M: …」这类任务步骤日志。

## 8. 复用与分享

- **复用**：同一个门户的多个方案可以绑定同一个直连任务，请求地址、请求头与判定关键字只维护一份；换账号只需在各自方案里填自己的账号密码。
- **导出 / 导入（文件）**：直连任务走任务页的导入 / 导出——「直连任务」子页顶部有「导入」「仓库导入」；每条任务行尾 `⋯` 菜单里有「导出 JSON」，任务编辑页头部也有「导出」，导出文件可直接回导。导入只收直连条目（文件里混着浏览器任务 / 脚本条目时会跳过并提示），导入后停在列表、需要自己点进去编辑。
- **任务仓库**：直连任务与浏览器任务在同一个任务仓库（`Misyra/campus-auth-tasks`）里，但**各有一份索引文件**——浏览器任务在 `index.json`，直连任务在 `index.http.json`（Gitee 镜像各为 `index.gitee.json` / `index.http.gitee.json`）。「直连任务」子页的「仓库导入」读的是直连那一份，「浏览器任务」子页读浏览器那一份。导入**直接落盘**（撞已有 ID 时自动加 `_2` 后缀，不覆盖）并当场打开该任务的编辑页，接着改即可。若某来源的该类索引里一个条目都没有，列表会说明「该来源暂无直连任务条目」——那不是加载失败。
- **方案分享不再携带直连配置**：分享方案只带认证地址、匹配规则与登录方式（凭据不随包导出），**不再包含直连的请求参数**。导入旧版（v9 及以前）导出的方案分享文件时，其中的直连字段会被**忽略**，并提示「该分享文件包含旧版直连配置，已忽略；请在「任务 · 直连任务」里重新配置」。直连任务本身照旧通过任务导出 / 任务仓库分享，不受影响。

## 9. 边界与已知限制

- **不处理验证码**：门户有图形验证码请继续用浏览器自动化。
- **不自动解析表单**：请求地址、请求头、请求内容都需要照抄开发者工具（或由脚本计算）。程序不做表单结构识别，也不做加密逻辑的自动逆向。
- **不回落浏览器**：直连失败按普通登录策略重试后终态失败，不会自动改用浏览器。
- **单次请求 20 秒超时**，最多跟随 5 次重定向，响应体最多读取 64 KiB。
- **只提交一次登录请求、不共享 Cookie**：程序不会先访问登录页再把 `Set-Cookie` 带到登录请求里（登录页原文只在配了凭据变换脚本时抓一次，且仅供脚本读取）。依赖 Cookie 的门户直连做不到，请用浏览器自动化；「先取令牌再提交」的门户可以用可选的**前置请求**表达（见 3.5）。除登录请求、前置请求与退出登录请求（见 3.6）外，程序不会再发别的请求——三者由同一个连接池顺序发出，顺序是「下线 → 读取登录页与执行脚本 → 前置请求 → 登录请求」。
- **HTTPS 证书**：默认跟随「设置 · 浏览器」的**忽略 HTTPS 证书错误**（默认忽略），与浏览器自动化一致——自签名证书的校园网门户因此可以直连。若你的门户证书正常，可在同一处把证书策略改为**严格校验**，降低携带凭据的请求被中间人截获的风险；改错会让自签名门户直接报证书错误。
- **不跟随系统代理**：直连请求始终直连网关（校园网网关是本机可达的内网地址，走代理必然失败）。若你需要经代理访问门户，请用浏览器自动化。
- **响应体解码**：优先按响应头声明的 charset，其次 UTF-8，最后按 GBK 兜底——国内大量校园网门户以 GBK 返回中文且不声明 charset，直接按 UTF-8 解会命中不了中文关键字。
- **配置体积上限**：请求地址 8 KiB、请求头 64 KiB、请求内容 256 KiB、关键字各 8 KiB、脚本 128 KiB；前置请求与退出登录请求的地址 8 KiB、请求头 64 KiB、请求内容 256 KiB、取值方式与占位符名各 8 KiB。**超过上限时保存会被拒绝**并给出「xx 过长（最多 N 字节）」，请裁剪后再存。请求头默认会带一个浏览器 User-Agent（未在请求头里显式写 `User-Agent` 时），部分门户/WAF 会因此正常返回；需要用自己的 UA 时直接在请求头里写一行即可覆盖。
- **GET 的凭据暴露**：GET 会把账号密码放进地址栏，网关、代理与系统网络日志仍可能记录完整地址。程序只保证**自身**日志与返回消息中的凭据已脱敏（含脚本产出的值及其 URL 编码形态）。能用 POST 时优先用 POST。
- **失败判定为终态且不重试**：命中失败关键字即结束本次登录尝试（例如「密码错误」重试无意义）；「未命中成功标识」才进入重试。

## 10. 常见问题

**升级后原来的直连配置去哪了？**
升级时会自动迁移（配置版本 v9 → v10）：每个配过直连的方案会得到一个名为「<方案名> 直连」的直连任务，并自动绑定好，方案里的直连字段随之清空——你不需要做任何事。迁移是**单向的**（搬完之后，旧版本程序再读同一份配置就看不到直连参数了）。若想把这份配置分享给同学，建议先打开该任务、把**认证地址**填进去，再导出或上传任务仓库。

**登录成功后界面仍显示离线？**
登录判定成功之后，程序还会做一次登录后网络探测复核（等待「登录后延迟」，默认 5 秒），只有探测确认在线才算真正成功。若持续离线，说明门户其实没接受这次登录——回到第 3.4 节检查关键字，尤其是「响应恒为 200」的门户。

**测试过了但自动登录还是失败？**
按这个顺序看：

1. 方案是否**绑定了直连任务**——「方案」页 → 「登录方式」→「直连任务」下拉不能停在「未绑定（直连登录不可用）」；绑定的任务后来被删掉也会让它失效。
2. 方案改动是否**已保存**：编辑器里的修改不点「保存方案」就不生效。
3. 任务改动是否**已落盘**：直连任务编辑器里的测试用的是当前内容，且任务改动会自动保存（头部状态字是「已保存 · 刚刚」）。**唯一例外是缺口态**——地址等必填项没补齐时状态字会说「有 N 处待补全，改动暂未保存」，此时自动登录用的仍是磁盘上的旧配置，表现为「测过了却失败」。
4. 需要密码加密的门户：确认凭据变换脚本已写进任务并保存。

**面板里没有「配置向导」入口？**
向导在**直连任务编辑器**里：「任务」页 → 直连任务 → 新建或编辑任务 → 右上角「配置向导」。方案编辑器里显示的是「配置直连任务」入口，点它会跳到任务页并打开所绑定的那个任务。

**脚本报「脚本执行超时」？**
脚本执行上限 500 毫秒，且没有网络访问能力。请在本地把耗时的查找、正则预处理搬到脚本之外（例如直接用门户返回的固定字段），或把大循环改写为直接定位。

**改了请求头但没生效？**
检查每行是否都是 `名称: 值` 格式（冒号后可有空格）。不含冒号的行会被静默忽略。改完不用点保存——任务编辑器里的改动半秒后自动落盘，看头部状态字确认即可。
