# 任务使用手册

任务是 Campus-Auth 的执行单元：浏览器任务用 JSON 步骤序列经 Playwright 执行，脚本任务经本地进程执行，直连任务描述一次直连登录请求的形状。文件存放在运行目录的 `tasks/browser/`（浏览器）、`tasks/scripts/`（脚本）与 `tasks/http/`（直连）下（`src/tasks/loader.rs`，`type` 缺失时默认归为浏览器任务以兼容旧 JSON）。

变量、步骤类型与字段语义见《任务编写指南》（`设置 · 任务与环境` 页可导出），本文只讲日常使用。

## 1. 核心概念

- **任务**：一份 JSON，`type` 为 `browser`（浏览器自动化）、`script`（脚本，`content` 或 `script_path` + `binary_path`/`args`/`work_dir`）或 `http`（直连登录的请求参数），见 `src/tasks/models.rs`。浏览器任务含 `url`/`steps`/`success_condition` 等；脚本任务由 `TaskExecutor` 直接起子进程执行；直连任务只描述「请求的形状」（方法/地址/认证地址/请求头/请求内容/成败关键字/可选的凭据变换脚本/可选的前置请求），账号密码仍在方案里。历史 `type=shell` 已移除，遇到时明确报错并提示改用 `script`。
- **启用任务**：实际被自动登录执行的任务，**按方案绑定**——每个 Profile 各有一个浏览器任务（`ProfileData.active_task`）与一个直连任务（`ProfileData.active_http_task`），切方案即切任务。在`方案`页的方案编辑器「登录方式」里选择，界面按当前渠道只显示对应的那一个下拉。浏览器渠道未绑定（或绑定的任务不可用）时回退内置默认任务 `default`；**直连渠道没有内置兜底任务**（门户地址因人而异，无法内置），未绑定即直连登录直接失败，方案编辑器会当场提示、保存时也会拒绝这种组合。
- **两类登录任务的异同**：都靠方案绑定生效、都在「任务」页的编辑器里编辑（选择绑定在方案页）；浏览器任务走 Python Worker 与 Playwright、可按步骤单步调试，直连任务在程序进程内直接发请求，**验证入口是编辑器里的「发送测试请求」（手填一次测试账号/密码），没有「调试」按钮**——它不经 Worker，无法单步执行。脚本任务不参与登录认证。
- **定时任务**：与登录任务独立，是「让某个浏览器任务或脚本按时跑一次」的**调度记录**（落盘 `<base>/tasks/scheduled/<id>.json`，执行历史在该目录的 `history/` 下；`src/scheduler`）。它不存登录参数，只记「目标 + 时机」——目标按 `target_id` 关联，任务类型由任务本体推导（`SchedulerService::task_type_of`），不在调度记录里冗余存储，故可调度的只有上述**两类**任务（浏览器 / 脚本）：直连任务不经调度，它的验证入口是任务编辑器里的「发送测试请求」。

## 2. 日常操作（Web 控制台）

### 任务页

侧栏「任务」项下收起五个子页（**默认收起**，点「任务」这一行本身即可展开 / 收起，行尾的箭头只是状态指示）：**浏览器任务**（自动化登录步骤序列）、**直连任务**（直连登录的请求参数，地址 `/tasks/http`）、**脚本**（定时执行的辅助动作）、**定时任务**（按时间或启动时机触发）与 **AI 生成**（用自然语言描述生成浏览器任务，悬停显示全称）。

- 新建、编辑、删除任务（**浏览器任务与直连任务还支持「复制为新任务」**）；列表可拖拽排序。**本页只管编辑任务内容**；「用哪个任务登录」在各方案的「登录方式」里选择。
- **编辑即自动保存**：四个子页（浏览器任务 / 直连任务 / 脚本 / 定时任务）都是「列表页 + 二级编辑页」——点行进入编辑页，面包屑「返回」回列表，字段改动停手半秒自动落盘（头部状态字：改动自动保存 / 保存中… / 已保存 · 刚刚 / 保存失败，修改后自动重试 / 有 N 处待补全，改动暂未保存；新建的草稿在第一次落盘前显示「尚未创建 · 改动后自动保存」）。地址（如 `?task=<id>`）会记住当前编辑的对象，刷新或分享链接都能直达编辑页——**新建的草稿在第一次落盘前不写这个参数**（磁盘上还没有它，带参会得到「找不到任务」），落盘后自动补上。
- **直连任务**：直连请求的全部参数都在这里编辑（不在方案的「登录方式」区域），落盘 `<base>/tasks/http/<id>.json`，同一个任务可被多个方案复用。任务编辑器里有「配置向导」（分步引导，改动与编辑器同步）、「发送测试请求」与「测试账号/测试密码」。详见 [直连请求登录使用指南](http-login-guide.md)。
- **脚本**：脚本 ID 就是任务文件名（落盘为 `<base>/tasks/scripts/<id>.json`，脚本正文在该 JSON 的 `content` 字段里；同目录下历史遗留的裸 `.py` 仍能被识别），新建时先命名——**打完名字按回车或点输入框外才会创建**（输入途中不落盘，避免把打了一半的名字存成文件名），落盘后 ID 固定；内容上限 100 KB，默认超时 60 秒。导出时才按脚本类型落到 `<id>.py` / `.sh` / `.bat`。详见 [自定义脚本指南](custom-script-guide.md)。
- **定时任务**：编辑页分三块——基本信息（名称 / 描述）、任务配置（目标类型 + 目标任务）、执行设置（触发方式「定时执行 / 启动后执行」及其参数，见下），侧栏是启停开关、触发摘要（「下次执行」或「今日成功 x/N」）、超时与任务 ID。列表里可直接「立即运行」与查看「执行历史」，开关控制是否按计划执行（**立即运行不受开关影响**）。非每日的 cron 表达式（步进、区间、星期限制等）在表单里表达不了：**只要不动「执行时间」，改名称或目标不会改动调度**（原表达式原样保留）；一旦动了「执行时间」，编辑页会当场明示「改了执行时间就会按上方时间改为每日执行」——那就按表单值改写。任务 ID 由程序生成、界面上只读；新建在名称与目标都补齐后第一次自动保存才创建，中途放弃不留文件。
- 从文件导入 / 导出单个任务（JSON 文件）。任务交换统一为导出结果格式（`{ summary, config }`，批量为其数组），导出文件可直接回导；导入另兼容顶层 `id` 的扁平对象与磁盘文件的 `task_id` 写法。各子页的导入各有口径：「浏览器任务」与「直连任务」只收自己那一类条目（其余条目跳过并提示忽略条数；`type` 缺省的条目按浏览器任务处理），「脚本」收的是脚本源文件（`.py` / `.sh` / `.bat` / `.cmd` / `.txt`），内容进编辑器等自动保存。**文件导入后停在列表**（需要自己点进去编辑），只有**仓库导入**是落盘后当场打开该任务的编辑页。

## 3. 任务何时执行

- **自动执行**：网络监测发现离线时，按当前方案的登录方式执行绑定的浏览器任务或直连任务（`设置 · 网络检测` 配置检测策略与重试）。
- **手动触发单次登录**：仪表盘的登录按钮（`POST /api/login`），执行当前方案绑定的任务。
- **执行指定任务**：`POST /api/tasks/{id}/execute`，不改变方案绑定，用于验证新任务。浏览器任务与脚本任务走这里；直连任务的验证入口是任务编辑器里的「发送测试请求」（直连不经 Python Worker，单步执行对其无意义）。

## 4. 录制器：不手写 JSON

录制器本身不产出任务，而是把你点选的元素整理成一段 **AI 提示词**；把它发给大模型，由模型生成任务 JSON，再导入到「任务」页。

1. 安装 Tampermonkey 浏览器扩展。
2. 在`设置 · 任务与环境`页点击`安装录制器脚本`。
3. 打开校园网登录页，点击页面上的浮动按钮开始录制。
4. 依次点选账号框、密码框、验证码（如有）、登录按钮等元素。
5. 点面板上的`📋 复制 AI 提示词`，粘贴给大模型，得到任务 JSON（也可用内置的「AI 生成浏览器任务」页完成这一步）。
6. 把生成的任务导入到`任务`页，再到「登录方式」里为当前方案选中它验证一次。

## 5. 验证码（OCR）

- 仅当任务中使用 `ocr` 步骤时才需要安装 OCR 依赖（约 120MB）。
- 在`设置 · 任务与环境`页安装，装好后可用`验证码识别`上传截图试识别，验证环境正常。

## 6. 调试

- 登录失败时先看`仪表盘`日志与失败截图（截图保留天数在`设置 · 系统`配置）。
- 需要单步排查时，使用 `POST /api/debug/start` 启动调试会话，或前端调试面板。调试只适用于浏览器任务；直连任务的对应入口是任务编辑器里的「发送测试请求」，它会回显实际发出的请求与响应（凭据已脱敏）。

## 7. API 一览

| 方法与路径 | 说明 |
| --- | --- |
| `GET /api/tasks` | 任务列表 |
| `POST /api/tasks` | 创建任务 |
| `GET / PUT / DELETE /api/tasks/{id}` | 查询 / 更新 / 删除 |
| `GET /api/tasks/export/{id}` | 导出单个任务 |
| `POST /api/tasks/import` | 导入任务 |
| `POST /api/tasks/order` | 排序 |
| `POST /api/tasks/{id}/execute` | 执行指定任务（浏览器 / 脚本通用；直连任务当前不可执行，用测试请求验证） |
| `POST /api/http-tasks/test` | 直连任务的「发送测试请求」：body 传请求参数 + 账号密码（不落盘，密码只在本次请求中使用） |
| `GET /api/scripts/binaries` | 可选解释器/二进制清单（脚本编辑器的 `binary_path` 下拉） |
| `POST /api/scripts/run` | 脚本直跑：body 传 `task_id`（执行已落盘任务）或 `script`（临时内容，不落盘，`task_id` 记为 `adhoc_script`）；二者均缺则 400 |
| `GET / PUT / DELETE /api/scripts/{task_id}` | 脚本单体读写（`ps1` 被拒） |
| `GET /api/scheduler/jobs` | 定时任务列表 |
| `POST /api/scheduler/jobs` | 新建定时任务（`cron` + 目标任务 `target_id`） |
| `PUT / DELETE /api/scheduler/jobs/{id}` | 更新 / 删除定时任务 |
| `POST /api/scheduler/jobs/{id}/toggle` | 切换启用 / 禁用 |
| `POST /api/scheduler/jobs/{id}/run` | 手动触发定时任务 |
| `GET /api/scheduler/jobs/{id}/history` | 定时任务执行历史 |
| `POST /api/login` | 触发登录（执行当前方案绑定的任务） |
| `POST /api/login/once` | 登录一次 |
| `GET /api/login/status` | 登录状态 |
| `POST /api/login/cancel` | 取消登录 |
| `GET /api/tools/task-recorder.user.js` | 任务录制用户脚本（Tampermonkey） |

## 8. 常见问题

- **任务执行失败**：查看日志定位到具体步骤；检查选择器是否随登录页改版失效；验证码步骤确认 OCR 已安装。
- **任务中使用变量**（仅浏览器任务）：在任务 JSON 的 `variables` 字段中直接定义，步骤内以 `{{变量名}}` 引用；`{{USERNAME}}`、`{{PASSWORD}}`、`{{ISP}}`、`{{LOGIN_URL}}` 自动取当前方案配置。脚本任务的 `content` / `args` **不做模板替换**（原样写入文件并传参），账号密码需在脚本内自行读取或硬编码。
- **多网络环境**：不同校区 / 运营商使用`方案`页的多方案切换，而非为每个环境各写一套任务。
- **脚本任务怎么写**：见 [自定义脚本指南](custom-script-guide.md)（`py`/`bat`/`sh`/`exe` 扩展名，`ps1` 不支持）；浏览器任务见 [任务编写指南](task-writing-guide.md)。
