# 更新日志

> 本文件面向使用者，按可发布版本汇总功能、体验和兼容性变化。开发过程中的每一项具体修改记录在 [`changelog.md`](changelog.md)；本文件自 2026-09-10 起启用，不迁移或改写此前的历史记录。

## 尚未发布（开发中）

### 不兼容变更

- **直连请求的配置从「方案」搬进了独立的「直连任务」**：以前直连的请求地址、请求头、请求内容、成败关键字与凭据变换脚本都写在方案里，一个账号只能一份；现在它们是一份**独立的任务**，方案里只保留账号、密码、认证地址与「用哪个直连任务」这一个选择。这样同一个门户的不同账号可以共用同一份请求配置，不必逐个抄一遍，也能把适配好的配置分享给别人。
- **升级时自动搬迁，你不需要做任何事**：每个配过直连的方案会得到一个名为「<方案名> 直连」的直连任务，并已自动绑定好，方案里原来的直连字段随之清空。这次搬迁是**单向的**——搬完之后，旧版本程序再读同一份配置就看不到直连参数了，所以升级后不建议回退版本。
- **旧分享文件里的直连配置会被忽略**：v9 及以前导出的「方案分享」文件里带着方案级直连字段，新版导入时会忽略它们，并提示「该分享文件包含旧版直连配置，已忽略；请在「任务 · 直连任务」里重新配置」。直连任务本身的分享走任务导出 / 任务仓库，不受影响。

### 新功能

- **任务页改版：列表页 + 二级编辑页，改动自动保存**：「浏览器任务」「直连任务」「脚本」三个子页统一为「整页列表 + 点行进入的二级编辑页」——列表铺满内容区（不再有一列被说明卡挤窄），点任意一行或「新建」进入编辑页，面包屑「返回任务 / 返回脚本」回列表，地址栏记住 `?task=<id>`（刷新、书签、把链接发给别人都能直达同一个编辑器）。列表行改成**两行**：名称下一行是描述（矮一号的灰字），一眼能看出这个任务是干什么的。**改动不再需要点保存**：字段改完停手半秒自动落盘，页头状态字显示「保存中… / 已保存 · 刚刚 / 保存失败，修改后自动重试」；必填项没补齐时状态字会明确提示「有 N 处待补全，改动暂未保存」，不会静默丢弃改动。脚本子页一并改用这套交互（此前仍是「保存脚本」按钮 + 未保存离开确认）。
- **「任务」页新增「直连任务」Tab**：直连的请求参数在这里新建与编辑，按填写顺序分六组（方法与请求地址、请求头与请求内容、成败判定、可选的凭据变换脚本、可选的前置请求、可选的退出登录请求），并带「配置向导」分步引导。向导与编辑器编辑的是同一个任务，改动同步并照常自动保存。
- **直连任务里新增「认证地址」**：填了就用任务里的，**留空则沿用方案里的认证地址**——本地自用不必填；要分享给别人时建议填上，否则对方还得自己摸出认证页地址。
- **直连任务可以复用、也可以分享**：多个方案（同一门户的不同账号）能绑定同一个直连任务，请求配置只维护一份；直连任务与浏览器任务在同一个任务仓库里**各有一份索引文件**（浏览器任务 `index.json`、直连任务 `index.http.json`，Gitee 镜像同样各一份），「直连任务」Tab 的仓库导入读的是直连那一份；导入即落盘并当场打开该任务的编辑页（撞已有 ID 时自动加后缀，不覆盖）。对方导入你的适配后，只需填自己的账号密码。
- **方案侧只负责「选一个任务 + 当场测试」**：方案编辑器的「登录方式」区域选「直连请求」后，会出现「直连任务」下拉（首项是「未绑定（直连登录不可用）」，可随时把任务摘下来），旁边可直接「发送测试请求」（用方案的账号密码发一次，不保存、不改变自动登录状态），并有一个入口跳去配置该任务。**直连没有内置兜底任务**（门户地址因人而异，无法内置），所以未绑定就保存会被拒绝并当场提示。方案编辑器本身仍是显式保存（方案里有凭据，改动不点保存不生效）。
- **直连任务也能拖拽排序了**：直连任务列表的**行首多了拖拽柄**，拖动即可调整顺序（与浏览器任务、脚本一致）。此前的顺序由文件名扫描决定、改不了。拖动任何一类的顺序都不会影响另外两类的顺序。
- **直连任务自带「发送测试请求」**：任务里不含凭据（账号密码属于方案），因此测试时手填一次「测试账号 / 测试密码」即可当场发一次真实请求；结果面板会回显实际发出的请求与响应，其中的账号、密码以及脚本产出的值都已替换为 `***`。
- **直连任务新增「前置请求」（可选的第五组）**：有些门户的登录要带一个先从别的接口取回的令牌（典型是 CSRF token），而且这个令牌**绑定连接**——取令牌与提交登录必须落在同一条连接上，否则门户直接拒绝。填了「前置请求」后，程序会先发这一次请求、把响应里的字段（如 `csrf_token`）取出来，再用**同一条连接**发登录请求；登录请求的请求头/请求内容里用 `{csrf_token}` 这样引用它。不需要前置请求就留空，整块忽略。**这一条把「两步式门户」从"只能用浏览器方式"变成直连也能做**（见下方说明的更新）。
- **直连任务新增「退出登录请求」（可选的第六组）**：有些门户在你还"在线"的时候会拒绝再次登录（提示「IP 已在线 / 重复登录」）。填上门户的下线接口后，程序会在登录**之前**先请求一次把旧会话踢掉，与登录请求共用同一条连接、同一套占位符（`{username}` 等），必要时还能设置「下线后等待」几秒等它生效。它排在所有事情最前面（先于读取登录页与凭据脚本）——旧会话还在时，这类门户的登录页会被重定向到「已在线」页，先清场再取值才对得上。下线请求的成败不影响登录：门户没开这个接口、地址写错，都只记一条日志，登录照常进行。不需要就留空，整块忽略。

- **「卸载」现在是真的卸载了**：以前点「卸载」只清掉开机自启动、加密密钥目录与 Playwright 浏览器缓存，最后一步"删除程序所在文件夹"得你自己去删（Windows 上运行中的程序删不掉自己，而程序文件与 `config/`、`tasks/`、`logs/` 同在一个目录里）。现在最后一步由更新助手在程序退出后完成：点「卸载并退出」→ 程序自动退出 → 删了什么、有没有删不掉的项，会用一个系统提示框明确告诉你。弹窗里还会**逐项列出**将删除的内容（程序目录、配置与方案、任务与脚本、日志、Python 环境、更新缓存，含具体路径），并多了一个「**保留配置与任务**」的勾选——勾上后上述用户数据整棵保留（**加密密钥目录也一并保留**，否则保留下来的方案密码根本解不开）、只删程序文件，方便你把便携版换个目录再装一次；重装后方案、任务、脚本、定时任务与日志都还在。为防止误删，程序目录看起来是**源码仓库**（含 `.git` 或 `Cargo.toml`）或**构建输出**（`target/` 下）时，卸载会被拒绝并说明原因；卸载助手缺失时会提前拦住而不是删到一半才失败。

### 说明

- 直连请求的边界：一次登录**只提交一次登录请求**（外加最多两次可选的附加请求：前置请求取令牌、退出登录请求踢旧会话），不携带 Cookie、不处理验证码；三次请求由同一个连接池顺序发出，因此「令牌绑连接」与「先踢旧会话再登录」的门户都能直连。需要多步交互、验证码或复杂跳转的门户，仍请使用浏览器方式。

### 修复

- **新建任务不会再悄悄吃掉另一类任务**：浏览器任务与直连任务的自动 ID 此前各按自己那一类编号，两边都会得到 `untitled_1`——而程序保存任务时会清理"同一个 ID 在另外两个列表里的残留文件"。于是"两类各建过第一个任务"之后，改一下直连任务就会把同名的浏览器任务文件删掉，界面上毫无提示。现在两类任务（含「复制为新任务」）取号时都会避开另外两类已用的 ID。
- **「保留配置与任务」保留下来的配置真的能用**：勾选它时程序仍会删掉加密密钥目录，而方案密码在配置里是密文——密钥一没，重装后所有方案密码都得重填。现在勾选后密钥目录一并保留（Playwright 浏览器缓存仍按系统残留清理）。
- **卸载助手缺失时不再"删到一半"**：以前会先清掉开机自启动与浏览器缓存，到最后一步才因为找不到卸载助手而失败——系统残留清了、程序却还在。现在探测阶段就检查助手是否在位，缺失时按钮直接禁用并说明原因（重新解压完整发布包即可）。
- **卸载后不会再被"更新回来"**：若卸载时正好有一次更新在下载、或更新助手已经在等待重启，程序退出后可能被更新助手装回来。现在卸载会先取消待应用的更新并复查是否真的取消掉了；万一没取消掉，退出前的回执会明确告诉你"程序可能被重新安装"。
- **定时任务不再"存不下去"**：新建定时任务时若第一次保存与后续改动叠在一起，任务其实已经建好了，界面却会一直报「该定时任务已存在」，之后每次改动都存不上，只能重开编辑页。现在这种"已经建好了"的冲突会被识别成成功并继续保存。
- **非每日的定时表达式不再被无关编辑改掉**：只在每周一跑（或按步进 / 区间跑）的表达式，以前只要在编辑页改了名称或目标，保存后就会被静默改成"每天 08:00"。现在只要不动「执行时间」，改别的字段就不会改动调度；动了时间控件才按表单值改写（编辑页会明示）。
- **新建脚本时名字不会被打字停顿锁住**：脚本 ID 就是文件名、创建后不可改，而此前"名字打到一半停手半秒"就会把它存成文件名并锁住输入框（`camp` 再也打不成 `campus`）。现在新建脚本要打完名字按回车、或点一下输入框外才会创建，输入途中不落盘。
- **危险步骤 / 凭据脚本的提示回来了**：改成"改动自动保存"之后，"保存前弹确认"那个时机其实已经不存在，于是含 `evaluate` 步骤（能在页面里执行任意 JS）的浏览器任务、含凭据变换脚本的直连任务都不再有任何提示。现在这两处会在编辑器里**常驻**说明，一眼能看到自己正在保存的是什么。
- **「放弃新建」不会再被迟到的保存写回**：编辑过程中换任务 / 关掉编辑器时，那一笔还来得及存的内容会先存好；而放弃、删除之后的迟到响应不再改写界面状态。
- **「定时任务」也不再开弹窗了**：它此前是任务页四个子页里唯一还要「填完点保存」的一个，而另外三个都是「点行进入编辑页、改动自动保存」。现在四个子页同一套交互：整页列表点行进入编辑页，面包屑返回列表，字段改完停手半秒自动落盘（页头状态字照旧说明「改动自动保存 / 保存中… / 已保存 / 有 N 处待补全」），没有保存与取消按钮。**名称与目标任务补齐前什么都不写**，所以新建任务不会在磁盘上留下半成品；编辑时侧栏会直接告诉你「下次执行」是今天还是明天、启动后执行的任务今天已成功几次。非每日的 cron 表达式（例如只在每周一跑）现在会在编辑页明说「保存后将改为每日执行」——这条以前只对部分写法生效，星期/日期限制的表达式会被静默改成天天跑。
- **从云端仓库导入时，两类任务不再混在一份清单里**：浏览器任务与直连任务此后**各有一份索引文件**，导入弹窗读的正好是你要的那一份。此前两类条目共用一份清单、靠条目里一个可选的类型标记区分，于是「漏了标记的直连条目」会以浏览器任务的身份出现在列表里，点导入得到的是一份没有登录步骤的空任务；现在这种情况不会再发生。顺带：某一类当前确实没有条目时，列表会明确说「该来源暂无直连任务条目」（从前这句话被说成"索引为空或格式不正确"，看着像出错）。
- **换任务时最后那几笔改动不再丢**：自动保存是"停手半秒落盘"，如果你在改完一个字段后立刻点开另一个任务（或从仓库导入、用浏览器前进/后退切任务），那半秒内的改动此前会既没保存也没提示地消失。现在换对象前会先把它存好，再打开你点的那一个。
- **编辑页状态字不再"说谎"**：配置内容被清空、或有 JSON 语法错误时，改动本来就存不下去，页头却仍写着「改动自动保存」。现在这两种情况都会改口（与"必填项没补齐"同一套提示），不会再让你以为已经存过。
- **「立即运行」的脚本结果就地显示**：脚本的输出以前只在"运行完成"的提示里一闪而过（而且无论成败都提示成功）。现在提示会如实区分成功/失败并带上退出码，编辑页侧栏还会留下这一次的输出正文——脚本为什么失败，终于有地方能看到。
- **定时任务手动「运行」的提示改口**：以前点下去就弹「执行成功」，其实只是"已排入执行"，任务随后失败也不会改口。现在提示「已触发执行，结果见「执行历史」」。
- **脚本 ID 的命名规则放宽了**：以前要求"字母开头、只能用字母数字下划线"，比程序实际接受的更严——一个名字里带连字符或数字开头的脚本会在编辑器里**既改不动也存不下**（ID 落盘后不可改）。现在与程序一致：1~64 位字母、数字、下划线或连字符。
- **「加载默认模板」会先确认**：这个按钮会用内置默认任务的配置整段替换你手写的登录步骤，并且立刻写盘——以前点了就直接覆盖。现在会弹一次确认（内容没改过或本来就是模板时不打扰）。
- **「分享适配」不再像一段裸文字**：它是「浏览器任务 / 直连任务」工具栏里的外链，此前只有文字没有底色与边框（夹在「导入」「仓库导入」两个按钮中间，看着不像能点）。现在与相邻按钮同一套外观。
- **导入任务时的类型说明**：从「浏览器任务」导入一份混着直连任务或脚本的文件，以前会提示"已导入 N 个任务"却一条也看不见（那些条目进了别的列表）。现在只导入本类条目，并明确告诉你忽略了几条。
- **浏览器任务被删除会提示影响面**：删除被方案绑定的浏览器任务后，那些方案会回退到内置的 `default` 任务——以前这件事不声不响。确认框里现在会说明。
- **连点不再重复触发**：浏览器任务的「调试 / 调试运行」在启动过程中会置灰（此前连点两下会发两次启动请求，调试会话可能被后到的那次覆盖）。
- **键盘可以直接跳到主内容**：按 <kbd>Tab</kbd> 后的第一个可聚焦元素是「跳到主内容」，用它可以直接越过整条侧栏。
- **导入脚本后会记住地址**：从文件导入一个已存在的脚本（覆盖）后，编辑器虽已打开、但地址栏不记这个脚本——改到一半刷新就掉回列表。现在与"点行进入"一样会记上。
- **「定时任务」页改版**：列表从"卡片 + 行尾四个按钮"换成与其他任务子页同一套表格（名称 / 类型 / 触发 / 目标 / 超时 / 最近结果 / 启用 / 操作），低频操作收进行尾 `⋯`，「启用」开关单独一列并带表头；**目标直接显示任务名**（不再只显示内部 id），目标任务已被删除时当场标红「目标已不存在」；停用的任务整行淡显但开关保持可点。新建/编辑弹窗的分区标题、执行时间字段一并收边，并补了页面上的 `?` 说明（定时任务只调度浏览器任务与脚本；直连任务的验证入口在任务编辑器里）。
- **新建任务不再「点一下就留一个空任务」**：以前点「新建任务」会立刻在保存目录里写一份占位任务，什么都没改就退出也留着它（列表里也会多一条「未命名任务」）。现在新建只是在编辑器里起一份草稿——**改了才创建**，不改就什么都不留；直连任务同口径。新建未落盘时状态字会说明「尚未创建 · 改动后自动保存」，头上的按钮这时是「放弃」（不会去删一个还不存在的任务），「调试运行」等入口会先置灰，地址栏也不会记下一个还不存在的任务。
- **改了又改回来，不会再动你的文件**：自动保存只在与磁盘上的内容确实不同时才写盘——新建后什么都没改就退出不留文件，字段改回原样也不会再写一次（文件的修改时间因此不会无谓变化）。脚本面板的新建草稿也补上了「导出 / 放弃」两个入口。
- **「调试」重新用回虫子图标**：浏览器任务列表行尾与编辑页侧栏的调试入口此前是播放三角，而编辑页里做同一件事的按钮是虫子——同一个动作两种图标；现在三处统一为虫子（脚本与定时任务的「运行」仍是播放三角，那是「运行一次」）。
- **任务列表的操作列居中了**：四张列表（浏览器任务 / 直连任务 / 脚本 / 定时任务）的操作按钮此前贴着右边缘，与行首居中的拖拽柄不成对；现在表头与按钮同轴居中，切子页也不再跳位。
- **定时任务的编辑弹窗与任务编辑页统一了**：分区改用与任务编辑页相同的卡片样式（此前是全站唯一一处 13px 带下划线的分区标题）、弹窗加宽到 720px、字段回到双列对齐；「定时执行」的触发方式 / 执行时间 / 超时并成一行，打开即可看全，不必先滚动。
- **定时任务的「执行历史」弹窗修好了**：条目样式此前全部失效（弹窗渲染在页面容器之外，样式却挂在页面容器上），「成功 / 失败」两个字被塞进 20×20 的图标框、时间与结果被挤成横排两列。现在与仪表盘的登录历史同一套样式：状态图标 + 时间 / 耗时 / 结果的纵向信息列，成功绿色、失败红色。
- **浅色主题下弹窗不再"发灰"**：弹窗底色此前与"次级面"同值（比页面卡片更暗），叠在遮罩上像一块灰板子；现在抬到卡片之上的一档，弹窗内的输入框改用比底面略深一档的底（与深色主题同一口径）。Toast、下拉菜单、向导这些悬浮面一起变亮。
- **任务列表的底色统一了**：此前表头与页脚各叠了一层浅色，数据行没有自己的底色，于是同一张卡片里出现三种灰——只有一条任务时那行看着像"被选中"。现在整张表就是卡片自身的表面，表头与页脚改用弱化字和分隔线表达（悬停时该行仍会整行变色，那是真的交互反馈）。
- **侧栏「任务」下的子项放大了一档**：浏览器任务 / 直连任务 / 脚本 / 定时任务 / AI 生成的字号与行高此前刻意比上一级小一档（13px、行高 33px），实机里读成"字太小"；现在与一级项同级（14px、行高 40px），层级由"无图标 + 左侧细轨 + 弱化色"表达。矮窗口下多出来的高度由侧栏内滚动承担，底部状态行不会被推走。
- **字段说明气泡（每个字段旁的 `?`）更好读了**：气泡宽度现在跟着文案长度和可用空间走（此前固定 460px，一句 38 字的中文会被折成两行半、末尾两个字单独掉到第三行；宽屏上右边空着一千多像素也没用上），并加了一个指向 `?` 的小箭头，长说明里也能看出这段解释属于哪个字段；钉住态（点击展开）同样显示箭头。另外修掉了"气泡下半截被下方卡片压出一条亮带"的层叠问题——任务编辑器里长说明跨过卡片边界时尤其明显。
- **任务列表最后几行的行尾「⋯」菜单点不到**：菜单被卡片圆角上的裁切（`overflow: hidden`）切掉，越靠下的行切得越多，最末一行只剩菜单顶边——看起来像"点了没反应"。现在菜单完整可见可点，卡片圆角改由表头/表尾单元格承担。
- **编辑页「返回任务 / 返回脚本」点了不回到列表**：浏览器任务子页的这个按钮此前只清了地址栏参数、没有关闭编辑器，点完仍停在编辑页（只能靠刷新离开）。现在返回即回列表，并在返回前把停手不足半秒的最后一笔改动补一次保存。
- **打开一个已被删除的任务会得到一整页空白**：从书签、历史或别人发的链接进到 `?task=<已删除的 id>` 时，页面整块空白、既没有提示也没有返回入口。现在会提示「找不到任务「xxx」，它可能已被删除」并回到列表。
- **搜索状态下拖拽排序会挪错任务**：列表按搜索过滤后，拖拽用的是"过滤后的位置"去改"完整列表"的顺序——中间有被过滤掉的任务时会挪错一条，并把错误的顺序保存下来（刷新后才看出来）。现在拖拽按真实位置计算，过滤状态下也拖不错。
- **自动保存被必填项拦住时状态字会说谎**：请求地址等必填项没补齐时改动本来不会落盘，页头却仍写着「改动自动保存」，关掉编辑器才发现改动没了。现在状态字改口「有 N 处待补全，改动暂未保存」，编辑页顶部还会列出具体缺什么，关闭编辑器时再提示一次。

## v5.0.2（2026-09-20）

### 修复

- **应用内更新下载完成后无法生效**：此前点「立即更新」下载完成后，若在弹窗中选择「立即重启」，程序会用旧版本生成一个替代进程再退出——替代进程恰好锁住主程序文件，导致更新助手替换失败（日志出现「替换失败: 另一个程序正在使用此文件」），重启后仍是旧版本，且已下载的更新包被清理、需重新下载。现在带待应用更新重启时不再生成替代进程，由更新助手完成替换后直接用新版本启动。手动选择安装包更新与定时自动重启场景一并修复；即便助手替换意外失败，也会保留已下载的更新包，下次启动自动重试应用，无需重新下载。

## v5.0.1（2026-09-19）

### 修复

- **「启动后执行：登录一次后退出」现在真的会退出**：此前选了该选项后，程序启动时确实会登录一次，但登录成功后并不退出，与界面承诺的「成功后自动退出程序」相反（典型场景：开机自启后登录一次即释放资源）。现在登录成功后程序自动走统一优雅关闭退出；登录失败或被取消时仍保持运行，便于打开 Web 控制台查看原因并重试。

## v5.0.0（2026-09-18）

### 不兼容变更

- **「用哪个浏览器任务登录」改为按方案绑定**：以前「浏览器任务」是全局唯一一份，在任务页点某行的「使用」按钮来选定；现在改为每个方案各自绑定，**切换方案即切换任务**，任务页因此只负责编辑调试，不再有「使用」按钮。升级时你原来的全局选择会**自动迁移给当前正在使用的方案**，不会静默丢弃；若绑定的任务被删除或改成了脚本，会回落到内置默认任务并在日志里告警。
- **认证地址收敛为「填了就直接用，留空就跟随重定向」**：方案页的「重定向模式」开关已移除。旧方案里已配好重定向触发地址的继续按重定向运行；当你在认证地址里填写固定网址时，程序会清除旧的触发地址，避免两个地址互相覆盖。触发地址的默认值与自定义入口收进「重定向高级设置」（默认折叠，非特殊网络无需修改）。
- **新增「登录严格模式」开关，默认开启**：开启时只在探测给出明确门户结论后才自动登录。若你的校园网是「先登录学校门户、再进入校园网认证并选择运营商」这类结构，严格口径可能一直不触发自动登录——**表现为断网后不会自动恢复**。遇到这种情况请到「设置 · 检测」页关闭「登录严格模式」（该开关的说明里也写了这条指引）。
- **界面导航固定为五项**：仪表盘 / 方案 / 任务 / 设置 / 关于。原来藏在「更多」菜单里的「定时任务」「外观」分别归入「任务」「设置」页，旧地址（如 `/scripts`、`/ai-task`、`/settings/environment`）仍会跳转到对应位置，书签不失效。

### 新功能

- **「设置 · 系统」新增「运行模式」**：把一组相关设置打包成两个预设，一键在「日常使用」与「排查问题」之间切换，不用再逐项猜该改哪几个开关。**默认模式**＝浏览器后台静默运行、启动后自动检测断线重连、开启开机自启、启用夜间暂停时段；**调试模式**＝显示浏览器窗口、登录后保留浏览器进程便于反复查看、记录调试级日志、启动后不自动登录、关闭暂停时段（随时手动复现不被拦）。切换前会列出**具体将要改动哪几项**（一行一项，左对齐列名、右侧列出「旧值 → 新值」），确认后才动手；时段起止不在预设覆盖范围内，你自定义的暂停时间段不会被切换抹掉。你手动调整过其中任一设置后，卡片会自动显示为「自定义」，此时点任一模式即可一键回到常规配置。
- **免 Python、免浏览器的「直连请求」登录方式**：适用于门户登录本身就是一个普通 HTTP 请求的学校——程序直接发出该请求完成认证，不下载 Chromium、不启动浏览器、不需要 Python 环境。在方案编辑器的「登录方式」处可切换「浏览器自动化 / 直连请求」，并配置请求方法、地址、请求头、请求体与成功/失败关键字。**边界说明**：直连目前只发一次请求，不携带 Cookie 会话，也不支持「先取令牌再提交」的两步式门户；这类门户请继续使用浏览器方式。判定只对响应正文做关键字匹配，因此响应恒为 HTTP 200 的门户必须填写成功与失败关键字。
- **直连配置向导（四步）**：确认账号与门户地址 → 照抄门户登录请求 → 设定成败判定 → 当场发一次真实请求验证。向导里改的内容会直接写回当前方案，关闭向导不丢，也不会自己保存。某一步必填项没填时「下一步」会禁用并在底部说明原因（例如「请先关闭向导，在上方页面填写账号并保存，再回来继续」），不会等到最后一步才告诉你缺东西。
- **直连请求登录使用指南**：「登录方式」区域的「使用文档」与向导第一步都可打开。内容涵盖怎么判断自己的门户适不适合直连、怎么用浏览器开发者工具找到登录请求、占位符与凭据变换脚本怎么写（含 Dr.COM / eportal 这类按本机 IP 加密门户的完整示例）、测试结果怎么解读。凭据变换脚本以沙箱 JavaScript 运行，脚本中可读到本机 `local_ip` 与 `local_mac`（部分门户的加密密钥由来源 IP 推导）。
- **方案可以导出分享给同学了**：在「方案」页，每个方案卡片上新增「导出」按钮，会把方案（认证地址、重定向触发地址、直连请求地址与请求内容、成败关键字、凭据变换脚本、网关与 WiFi 匹配规则等）存成一个 JSON 文件；对方在「方案」页点「导入方案」选择该文件即可用。导出**不含账号与密码**，导入后由对方填写自己的——因为密码是加密存储的、脱离本机无法解密。方案名重复时自动改名，不会覆盖对方已有方案。
- **导入他人方案前会先展示内容**：确认弹窗里能看到方案名、登录渠道与匹配规则；如果该方案含凭据变换脚本（登录时会执行的 JavaScript），会把脚本原文摊开显示，并标注它在无网络、无文件的沙箱中运行，确认来源可信后再导入。
- **定时任务新增「启动后执行」**：与原「定时执行」二选一。软件每次启动后延迟执行目标任务，解决定时触发在未开机时段漏跑的问题（典型场景：网站签到，配合开机自启实现「每天开机后自动签到一次」）。可设每日成功上限（默认 1，达到后当日自动跳过、跨天重置）、失败重试次数（默认 2，轮内间隔 1 分钟）、延迟秒数（默认 30，用于等网络或校园网登录就绪）。手动执行不受额度限制，但手动执行成功同样计入当日额度，避免在延迟窗口内重复触发。
- **方案页新增「重定向检测」**：位于「认证地址」上方，先用一次 HTTP 预检识别当前是否已联网并提示退出校园网登录；其余情况强制启动可见浏览器，在独立临时会话中等待跳转，并综合页面地址、表单结构与「校园网 / 登录 / 认证」等中英文语义判断。识别到认证页时提示认证地址无需填写，未识别时提示重试或手动填写。检测全程不修改方案草稿，也不复用你正常登录的 Cookie / 本地存储。
- **AI 生成浏览器任务增强**：页面捕获新增结构化上下文（表单、控件、label、下拉选项、验证码候选、Shadow DOM 信号与稳定选择器候选，另保留脱敏后的局部 HTML）；模型配置改为面向新手的服务商卡片向导，新增「测试连接」并显示实际请求地址与耗时，DeepSeek / GLM / OpenCode / 自定义服务各用独立加密 Key 槽位，切换服务商同步切换 Key；输出长度开放 16K / 32K / 服务商默认三档，默认提高到 16384。生成仅允许新建浏览器任务，且必须使用 `{{LOGIN_URL}}`，执行 JavaScript 步骤需二次确认。
- **更新可以不走联网下载了，两种方式**：① 在「设置 · 网络与更新」直接**点「选择安装包」**挑一个本机已下载好的压缩包（`.zip` / `.tar.gz` / `.tgz`，最大 512 MB）即开始更新——适合下载慢、或你用的是自编译包 / 别人重打包的镜像包；这种方式**不核对远程发布的校验值**（自编译包的摘要必然与官方不同），所以请只选你信任来源的包。② 把发布包**放进程序数据目录的 `update/` 文件夹**，再点「立即检查」——若内容与远程发布一致，会提示「已在 update/ 目录找到匹配的安装包 xxx，更新时将跳过下载」，按钮相应变为「使用本地包更新」。两种方式都有硬性检查：版本必须高于当前、包内必须能解出主程序；不通过会直接拒绝并说明原因。更新页顶部新增说明条，展开后会显示你机器上 `update/` 目录的实际路径并支持一键复制。

### 体验

- **软件中文名改为「认证喵」**：界面标题、侧栏、顶栏、托盘提示与安装向导统一使用新名称；英文标识、仓库名、二进制名等技术标识一律不变。
- **「方案」成为账号类的唯一入口**：账号、密码、认证地址、匹配规则、登录方式与直连参数都在同一封表单里，保存一次全部落盘——不必再先翻列表找卡片点「编辑」。打开这一页会**直接停在当前正在使用的方案**上，标题右侧的下拉可以在方案之间直接切换，标着「当前使用」的那个就是自动登录实际用的方案。此前同一份数据有三个可写入口（「设置 · 账号」、「配置方案」编辑器、「任务」页的直连登录标签），容易出现「在这边改了却没生效」。
- **能看清密码到底是「已保存」还是「没设置」了**：此前方案的密码输入框无论有没有密码都显示为空。现在会显示「已保存，留空保留；输入新密码则更新」或「未设置密码」，已保存时另有「清除已保存密码」按钮（可「撤销清除」）。
- **不再把探测到的门户地址自动填进表单**：方案页、直连向导与 AI 捕获页的「自动检测 / 检测并填入」已移除——那些地址可能带一次性 token，回填进表单并保存反而会污染后续登录目标。检测入口保留，但不再改写你的配置。
- **托盘菜单精简**：改为「状态行 → 分隔线 → 启动/停止监测（随状态切换）→ 手动登录 → 打开控制台 → 退出」，移除「检查更新」（更新入口统一收敛到关于页与「设置 · 网络与更新」）。状态行由「当前状态：运行中 · 在线」改为「状态：运行中 · 在线」，运行中为深色、已停止为灰化，符合系统原生菜单的主次表达。
- **全站字体改为 Noto Sans SC（可变字重）**：中文不再依赖各系统默认字体的拼凑效果；字体按需从 CDN 分片加载，仓库与安装包内不再分发字体文件，断网时回落系统字体栈，不阻塞首屏、不白屏。
- **「关于」页新增「B 站主页」入口**；**使用教程视频**入口放在「任务」页（与「安装录制器」并列——你正是在那里装录制器、需要看怎么用），教程直接定位到录制器的演示片段。「设置 · 任务与环境」的录制器卡片与 AI 生成页的排障提示也各有一处入口。
- **「设置 · 外观」的主题色默认改为黑白**：新安装与点「恢复默认」后，主题色为**日间黑、夜间白**（此前是青色）。选「跟随系统」时，白天用黑、夜里自动换成白。色板新增「黑白（日间黑 / 夜间白）」一项，色块会显示该主题下实际生效的颜色；其余 7 个彩色仍在，**已在使用中的配置不受影响**（你原来选的青色等会保留）。单色主题色下，按钮发光与描边改为中性灰而非彩色，开关的滑块也会自动取对比色以免和轨道同色看不清。
- **指南改为「下载」语义**：编写指南 / 任务手册 / 直连登录指南三个地址在浏览器中打开即弹出保存对话框，不再把 Markdown 原文铺在页面上；直连配置界面里的「使用文档」入口改指在线文档（离线时仍可访问内置地址）。
- **环境页改为五项常驻状态清单**：uv / Python / 认证核心 / 浏览器 / OCR 各自显示状态，未就绪与「可选」状态一眼可辨，不再只展示正向徽标。Python 环境卡片置顶并支持折叠：就绪时自动收起，异常或初始化中自动展开，点头部可手动切换。设置页的「任务」「环境」两个 Tab 合并为「任务与环境」。
- **已有系统浏览器时不再下载 Chromium**：检测到本机已装 Edge/Chrome 时跳过约 150 MB 的 Chromium 下载，仅在完全没有可用系统浏览器、或你在设置页显式安装时才下载。
- **登录历史与日志占用可预期**：登录历史固定保留 30 天（与界面查询窗口一致）；日志文件总量超过 200 MiB 时从最旧的轮转文件开始清理。
- **方案编辑器里的「网络匹配」默认收起**：网关 IP / WiFi 名称这两项只有多网络环境才用得到。如果该方案已配过匹配规则，打开时会自动展开；折叠状态下也会在标题旁显示已配内容（如「网关 192.168.7.7 · SSID Dorm-9F」），点标题即可展开或收起。
- **浅色主题文字更清晰**：正文、次级与说明文字整体加深到黑色系（正文纯黑，最浅一档在浅色背景上仍有约 7.9:1 的对比度）。深色主题不受影响。
- **直连配置界面重做**：渠道选择改为两张说明卡片，直接标出「需要 Python 与浏览器」还是「免 Python 与浏览器」；直连的各输入按填写顺序编号分组，每组说明这一步该做什么，并附「填入示例」按钮与占位符速查；密码加密脚本默认收起。
- **测试失败后知道下一步该改哪里**：发送测试请求的结果面板在结论之外新增针对性指引，例如「未命中成功标识」会直接提示去核对成功关键字，并提醒「响应恒为 HTTP 200 的门户必须填写成功与失败关键字，否则密码错误也会被判成成功」；请求报文与响应片段收进折叠区，脚本报错单独高亮。
- **「浏览器任务」下拉不再出现两个等同的选项**：此前首项是「使用内置默认任务」，而列表里又有一个「通用登录」——两者其实是同一个任务。现在只保留任务列表本身，其中内置的那条标注为「通用登录（内置默认）」。
- **「从云端仓库导入任务」更好用了**：来源选择（GitHub / Gitee / 自定义）从一串按钮改成分段控件，和「加载索引」放在同一行；选中来源下方会说明这个来源的特点；还没加载任务时不再是一片空白，而是明确告诉你点哪里开始，并给一个直达仓库的入口；底部提示也跟着状态变（还没选任务 / 已选中可导入）。
- **国内用户下载任务列表时不再干等**：导入任务弹窗会说明每个来源的特点——选 GitHub 时提示「国内访问可能较慢或加载失败，卡住时请改用 Gitee 镜像」，选 Gitee 时标注推荐国内用户使用。卡住时切换来源即可。
- **新安装不再默认开始检测、也不默认自动切换方案**：此前程序启动就会立刻开始网络检测，单网络环境用户的「自动切换方案」也在后台每 60 秒空转一次。现在两个开关默认都是关闭的——启动后停在待机状态，在控制台点「启动检测」即可开始；需要多网络自动切换的到「方案」页开启「自动切换」。
- **新安装默认启用夜间暂停时段（23:00–06:00）**：宿舍定时断网时段反复重连没有意义。时段起止可在「设置 · 检测」页调整，也可以整体关闭。**已在使用中的配置不受影响**：升级后你原来的暂停时段设置会被完整保留（包括已经关闭的），上述两项默认值同理。
- **界面细节**：仪表盘的登录历史、自定义脚本、定时任务空态补齐下一步操作引导；仪表盘网络横幅按状态分级（一切正常时收进标题旁的 `?` 悬浮气泡，门户劫持 / 离线 / 冷却 / 暂停等异常态说明原地直显）；「设置 · 检测」的 204 门户检测去掉「（主要）」后缀改为「推荐开启」徽标，检测目标改多行输入并兼容英文逗号分隔；任务列表为空时改单列顺排；修复任务页按钮尺寸、控件字体与窄屏（460px 级）折行溢出，以及「外观」页不再显示用不上的「立即保存」（外观改动即时生效并存在本机，点保存只会得到「配置没有变更，无需保存」）。

### 性能

- **登录历史接口不再随历史条数变慢**：此前每次刷新历史都要把 30 天的记录全量读出来再截断，累计历史越多越慢（2 万条时单次约 61 ms）。现在按天倒序读取、凑够所需条数即停止，2 万条时约 1.8 ms，且不再随历史总量增长。
- **多标签页同时开着更省内存**：日志实时推送的每个连接此前固定占用约 150 KB 缓冲（16 个标签页合计约 2.5 MB）。现在按实际流量收窄缓冲区，每个连接约 33 KB，16 连接合计约 0.5 MB，**降低约 79%**，消息接收能力不变。

### 修复

- **「任务录制器」的说明不再让人以为点完就有任务**：录制器实际不产出任务，而是把你点选的元素整理成一段 **AI 提示词**——需要在面板上点「📋 复制 AI 提示词」，再粘贴给大模型生成任务 JSON。此前任务页的面板入口、设置页的录制器卡片，以及录制器自身的说明与 Tampermonkey 安装页描述，都写成「自动生成任务」，容易让人以为点完元素就完事了；指南里的操作流程也漏掉了「交给 AI」这一步，现已全部补齐（录制器自身站点描述同步修正，旧描述里的「结构化文档」出口并不存在）。
- **AI 生成页的排障指引此前指向不存在的内容**：原文写「按照视频教程操作」，但程序里从未提供过任何视频地址，照着找必然落空；同句的页面路径也写成了旧名。现在直接给出使用教程视频（定位到录制器演示片段）与正确的「设置 · 任务与环境」入口。
- **「设置 · 任务与环境」的指南按钮文案自相矛盾**：按钮写「导出编写指南」，同一张卡片下方却写「点击即下载」。三个指南地址现在都会直接下载，按钮统一改为「下载编写指南」。
- **配色相关的三处看不清问题**：① 外观页色块上的勾选图标此前继承文字色，深色主题下是白色，叠在纯白色块（选「黑白」的夜间态、背景色的「纯白」）上完全看不见，现按色块实际底色自动取对比色；② 开关打开后的滑块此前固定为白色，若主题色是白色（黑白的夜间态）会与轨道同色而隐形，现已自动取对比色；③ 设置页下拉框聚焦时的小箭头此前写死了旧的青色，与新的黑白主题色不搭，现改为白 / 黑。
- **重定向门户「明明没网却一直不登录」**：部分校园网在严格模式下会把所有公网探测请求直接丢弃，程序因此恒判离线并停在「等待网络」，永远不启动浏览器。现在当方案确实使用重定向、探测未确认在线、但本地网卡有可用地址时，会标记为低置信度结论并谨慎启动一次浏览器访问触发地址；物理链路不可用、网卡检查失败或未启用任何有效探测时仍保持原结论，且同一门户事件只放行一次，避免普通断网时反复拉起浏览器。
- **直连登录补齐四处**：① HTTPS 证书策略可配——此前直连使用严格证书校验，而浏览器方式默认忽略证书错误，自签名证书的校园门户会出现「浏览器能登、直连必然失败」且无从调整；② 统一补发浏览器 User-Agent——部分门户或 WAF 因缺少该请求头返回 403，表现为「抓包看不出问题、直连就是失败」；③ 测试结果面板新增响应头——排查中文乱码导致关键字命中不了、302 跳转去向等问题的线索正是 `Content-Type` / `Location`；④ 超限的直连配置在**保存时**即被拒绝，不再出现「保存成功、登录时才报过长」。
- **任务执行的提示不再混淆「跑完」与「认证成功」**：浏览器任务的「成功」只代表步骤都执行完了，后端不做登录后网络验证。未声明成功条件的任务现在提示「已执行完成（未校验结果）」，已声明的提示「执行完成」；任务页新增「如何判定任务真的成功」说明，含可复制的示例用于校验业务结果。
- **首次启动会写入默认 `settings.json`**：此前默认值只存在于内存，用户找不到配置文件，排障时也无从核对实际生效值。写入失败仅降级为沿用内存默认并记日志，不阻断启动（只读介质场景不应起不来）。
- **任务页顶部补提示「请前往『方案』选择并启用任务，此处仅编辑调试」**：此前在本页建的任务不会自动生效（登录执行的是方案绑定的任务），但界面没有任何说明，用户也无从得知该绑定关系在哪里修改。
- **OCR 状态不再看起来像「装了空壳」**：区分「已加载」「依赖已装、运行时未加载（首次使用时自动加载）」「需处理」三种状态，避免把「按需懒加载」误读为安装失败。
- **系统通道浏览器缺失时给出可操作提示**：此前只报「未上报缺失组件明细」，排障方向被带偏到「Worker 启动超时」。现在直接提示（如「未检测到 Microsoft Edge，请安装 Microsoft Edge 或改用 chromium」），并区分「可自动重装」与「无法自动安装，请按提示处理后重试」，不再宣称一个不存在的自愈动作。
- **命令行输出在 GUI 构建下不再被静默丢弃**：`campus-auth --version > out.txt`、`--status > out.txt`、以及管道输出等场景此前得到 **0 字节且退出码为 0**，现已完整输出（仅重定向 stdout、stdout+stderr 双重重定向、管道三种场景均验证）。
- **修复远端字体实际从未生效**：内容安全策略只放行了字体文件来源，未放行样式表来源，导致字体样式表被浏览器拦截，界面始终回落系统字体栈。现已修正（脚本来源仍限本地）。
- **默认端口被系统保留时不再启动失败**：Windows 上 WinNAT / Hyper-V 可能保留端口，此前会导致 Web 控制台以错误 10013 起不来。现在本地访问的首选端口确属占用或保留时，改由系统分配一个可用端口，并把实际端口同步到实例记录与控制台地址；面向局域网或 Docker 的监听仍保持固定端口失败语义（便于发现配置问题）。
- **任务文件带 BOM 时不再从列表消失**：用 Windows 记事本保存过的任务文件会带 BOM 前缀，此前解析失败导致任务静默消失，现在可正常加载。
- **调试页「导出问题报告」不再遗失内容**：此前 HTML、MHTML、截图与 CSS/JS 资源会因落盘目录与安全守卫不一致而缺失，现已统一。
- **「纯净模式」开关不再被静默翻回**：此前关闭后，只要在任意设置页点一次「立即保存」，它就会被悄悄恢复为开启——而界面开关仍显示「已关闭」，与实际配置不一致，也没有任何提示。
- **Engine 异常重启瞬间不再报「服务故障」**：引擎崩溃并自动重启的短暂窗口内，点击「开始/停止监测」或「测试网络」会收到 HTTP 500（表现为服务端故障）。现在改为 503 并提示稍后重试，符合实际情况。
- **任务执行失败不再弹绿色「执行完成」**：此前任务实际失败时也会显示成功样式的提示（后端以 HTTP 200 返回，失败信息在响应体内）。现在按真实成败分流：失败以错误样式提示，并优先展示后端给出的失败原因。
- **定时任务不再被并发的登录打断**：此前登录与定时浏览器任务在后台共享同一个执行槽位，登录失败重试时会连带回收 Worker，导致正在进行的定时任务中途失败，且历史里只留下「请求已取消」——看起来像是被主动取消，实际与用户操作无关。现已改为只回收属于本次登录的资源，不影响他人。
- **卸载 OCR 依赖时不再打断正在进行的任务**：此前若有定时任务或登录正在进行，点「卸载 OCR 依赖」会连带把那个任务掐断，而任务历史里只留下「请求已取消」。现在这种情况会直接提示「有任务正在执行，请稍后再试」，等任务结束后再卸载即可。
- **日志面板刷新不再丢实时日志**：此前点过「清空」后再点刷新，刷新期间新到达的实时日志会被整批丢弃，「N 条新消息」提示也一并消失。现已保留。
- **关闭严格登录模式后，界面不再把「确认检测到门户劫持」说成「按链路推断」**：此前关闭「登录严格模式」会把一次明确的劫持检测降级显示为推断结论（置信度从高降为低），排障时无法区分两者；同时会绕过「同一配置只谨慎尝试一次」的节流。现已保留原始结论。
- **后端长时间无响应时，界面能正常报超时**：此前若响应头已返回但响应体卡住，请求会永久挂起（一直转圈、无提示、保存按钮卡住）。现在超时与取消覆盖到完整响应。
- **被取消的登录不再被报成「重试耗尽」**：用户主动取消、被新请求抢占、以及程序关闭这三类情况此前可能显示为「重试次数已用完」，现在统一按「已取消」呈现，只有真正的失败才计入连续失败冷却。
- **更新过程中的进度不再被清零**：此前在下载或应用更新的同时触发一次检查，会把「更新中」误报回退成「无更新」并把进度清零；现在更新进行中不再合并检查结果。下载失败时残留的半写入临时文件也会立即清理，不再等到 3 天后才回收。
- **弹窗里的确认框不再被弹窗本身挡住**：此前在弹窗内发起确认时（如「关于」页点「卸载」后再点「开始清理」），确认框会显示在该弹窗的下层、必须先手动关掉弹窗才点得到确认。现已确保确认框始终显示在最上层，在弹窗内可直接确认或取消，取消只关闭确认框、不会连带关掉当前弹窗。
- **任务页「分享适配」按钮指向了错误的仓库**：它的用途是「把你适配好的登录任务分享给社区」，但链接指向了程序本体的代码仓库（点进去只有源码），而任务实际存放在单独的任务仓库里。现已修正。
- **导入任务弹窗里「直接查看仓库」不再点出一屏乱码般的原始文本**：该链接此前指向程序读取任务列表用的索引文件地址，点开看到的是原始 JSON。现已改为指向仓库主页。
- **还没加载任务时不再提示「点击左侧任务查看详情」**：列表为空时左侧根本没有任务可点，提示指向了不存在的东西。现在这种情况显示的是核对提示。
- **账号的「自定义运营商」不再意外回落**：此前下拉选择自定义运营商并输入关键字后，若把自定义文字全部删除，会意外回落到「不选择」；现已保持「自定义」选项与输入框。
- **方案相关**：账号框此前提示「留空使用全局」，但程序里并没有「全局账号」这回事，且登录失败时会引导到设置页去改（实际改的是当前方案）——现已改为「留空无法自动认证」并把填账号的位置统一到「方案」页；方案 ID 里含下划线（或名称含空格/中文）导致「创建后无法再编辑」的问题已修复（下划线与连字符都接受）。
- **「登录方式」的引导更完整**：直连渠道下不再显示「Python 环境未就绪」横幅（直连不拉起 Python 与浏览器，该提示与它无关）；向导与使用文档入口在离线时仍可访问。
- **修复点「选择安装包」会让页面刷新一下**：该按钮此前会触发整页刷新，并把地址栏里的鉴权参数冲掉。原因是设置页外壳用了一个只为「浏览器自动填充」而存在的表单容器，而按钮未显式声明类型，浏览器便按规范把它当成「提交表单」处理。现已从根上拦掉该表单的提交行为，并给相关按钮补齐类型声明——同类问题不会再出现（已加静态检查拦住回归）。

### Docker 部署

- **「安装录制器」按钮不再 404**：`resources/` 此前未随运行镜像分发，导致该接口找不到脚本文件。现已随镜像分发并在每次启动时同步到数据目录（覆盖同名、补齐缺失，升级镜像后不会残留旧脚本；同步失败仅告警，不阻断启动）。
- **容器停机不再留下孤儿浏览器**：`docker-compose.yml` 补 `stop_grace_period: 40s` 与 `init: true`。程序优雅关闭预算约 26 秒（托盘 + 调度 + 引擎 + Bridge + Web），而 Docker 默认 10 秒后即强杀，会在等待 Worker 退出前打断并留下 chromium 进程；`init` 负责回收浏览器子进程树的僵尸进程。
- **容器内不再安装开发依赖**：`uv run` 步骤此前会把 `pytest` 等开发依赖重新装回环境，现已统一对齐到不装开发依赖的口径。
- **部署文档口径修正**：根 `README.md` 的 `docker run` 示例补 `--restart unless-stopped` 与 `--stop-timeout 40`，并把端口改绑回环（原写法把所有网卡都暴露出去，与同项目文档「不要把容器端口直接暴露到局域网或公网」自相矛盾）；缺 `--restart` 时，默认 24 小时自重启到期后容器会停在 exited 不再回来（compose 文件已有该策略，故不受影响）；`docker/README.md` 明示「容器内不支持应用内自更新」，容器内 Worker 位于镜像目录而非数据目录，更新应由部署系统完成。

### 网络监测与自动恢复

- 默认仅开启 HTTP 204 门户检测；TCP 与 URL 内容检测改为按需启用的补充手段
- 网络结论新增“等待检测/证据不足”状态，不再把探测关闭、弱证据或互相冲突的结果误报为离线
- 自动监测、手动诊断和登录后验证采用各自独立的行为：手动诊断不会触发登录，暂停期间也可以执行
- 仪表盘现在会说明网络结论的原因，以及系统接下来会保持观察、尝试登录还是等待修复配置

### 安装、Docker 与发布

- 修复 OCR 依赖安装/卸载时命令拼接错误，`ddddocr` 仍然仅在用户启用 OCR 时按需安装
- Python 环境现在会分别验证解释器、Worker 依赖、版本和浏览器；即使电脑已有 Edge/Chrome，也不会再把缺失的 Playwright Python 包误判为可用
- Worker 首次启动失败时会自动修复环境并重试当前操作，修复成功后自动解除熔断；“重新同步”按钮会执行一次真正的完整校验与同步
- 若 uv 管理的底层 Python 已被系统清理，程序会安全重建损坏的虚拟环境；重建失败会保留并恢复原目录，不再反复复用一个看似存在但无法启动的环境
- OCR 偏好独立保存，安装失败后可在后续自动重试；OCR 只准备 Worker 核心，不会额外触发 Chromium 下载，也不会因自身安装失败阻断普通登录
- Docker 构建现在严格验证 Worker、Playwright 和 Chromium，任一缺失都会阻止构建，避免启动后才发现 Worker 无法登录
- Docker 默认改为拉取 GHCR 预构建的 x64/ARM64 多架构镜像，不再要求每台部署机器重复编译 Rust、前端和 Chromium；源码构建仍可通过独立覆盖文件启用
- 发布页会自动读取本文件中对应版本的更新内容；便携包同时附带更新日志、更改日志、已知问题和许可证
