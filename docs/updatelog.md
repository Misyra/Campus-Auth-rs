# 更新日志

> 本文件面向使用者，按可发布版本汇总功能、体验和兼容性变化。开发过程中的每一项具体修改记录在 [`changelog.md`](changelog.md)；本文件自 2026-09-10 起启用，不迁移或改写此前的历史记录。

## 尚未发布（开发中）

> 已合入代码但尚未发版，随下一个版本号一并发布。用户可感知的变化如下。

### 新功能

- **「设置 · 系统」新增「运行模式」**：把一组相关设置打包成两个预设，一键在「日常使用」与「排查问题」之间切换，不用再逐项猜该改哪几个开关。**默认模式**＝浏览器后台静默运行、启动后自动检测断线重连、开启开机自启、启用夜间暂停时段；**调试模式**＝显示浏览器窗口、登录后保留浏览器进程便于反复查看、记录调试级日志、启动后不自动登录、关闭暂停时段（随时手动复现不被拦）。切换前会列出**具体将要改动哪几项**（只列真正会变的），确认后才动手；时段起止不在预设覆盖范围内，你自定义的暂停时间段不会被切换抹掉。你手动调整过其中任一设置后，卡片会自动显示为「自定义」，此时点任一模式即可一键回到常规配置。
- **界面按「配置的对象」重新组织，每类设置只有一个入口**：此前账号既能在「设置 · 账号」改、又能在「配置方案」编辑器改，「任务」页还另有一个直连登录标签——同一份数据三个可写入口，容易出现“在这边改了却没生效”。现在导航固定为**仪表盘 / 方案 / 任务 / 设置 / 关于**五项，每项对应唯一的数据：账号、密码、认证地址、登录方式、直连参数全部在「**方案**」页编辑（登录用的是“当前方案”的账号，切换方案即切换账号）；「任务」页管浏览器任务、脚本、定时任务与 AI 生成浏览器任务；「设置」页只管全局项（检测、浏览器、任务与环境、系统、网络与更新、外观）。原来藏在「更多」菜单里的「定时任务」「外观」也分别归入「任务」「设置」页，不再需要展开二级菜单。
- **任务页的「AI 生成」标签改为「AI 生成浏览器任务」**：和旁边的「浏览器任务」并列时，原先只写「AI 生成」看不出生成的是什么，现在一眼就知道这一栏产出的是浏览器任务（也正是登录实际执行的那一类）。
- **「配置方案」现在就叫「方案」，并成为账号类的唯一入口**：填账号请到这里。打开这一页会**直接停在当前正在使用的方案**上，账号、密码、认证地址、匹配规则、登录方式（浏览器自动化 / 直连请求）与直连参数都在同一封表单里，保存一次全部落盘——不必再先翻列表找卡片点「编辑」。标题右侧的下拉可以在方案之间直接切换，标着「当前使用」的那个就是自动登录实际用的方案。
- **能看清密码到底是“已保存”还是“没设置”了**：此前方案的密码输入框无论有没有密码都显示为空，看不出来。现在会显示「已保存，留空保留；输入新密码则更新」或「未设置密码」，已保存时另有「清除已保存密码」按钮（可「撤销清除」）。
- **配置方案可以导出分享给同学了**：在「方案」页，每个方案卡片上新增「导出」按钮，会把方案（认证地址、直连请求地址与请求内容、成败关键字、凭据变换脚本、网关与 WiFi 匹配规则等）存成一个 JSON 文件；对方在「方案」页点「导入方案」选择该文件即可用。导出**不含账号与密码**，导入后由对方填写自己的——因为密码是加密存储的、脱离本机无法解密。方案名重复时自动改名，不会覆盖对方已有方案。
- **导入他人方案前会先展示内容**：确认弹窗里能看到方案名、登录渠道与匹配规则；如果该方案含凭据变换脚本（登录时会执行的 JavaScript），会把脚本原文摊开显示并标注它在无网络、无文件的沙箱中运行，确认来源可信后再导入。
- **直连登录配置向导**：方案编辑器的“登录方式”区域新增「直连配置向导」入口，按四步配好免 Python、免浏览器的直连登录——确认账号与门户地址 → 照抄门户登录请求 → 设定成败判定 → 当场发一次真实请求验证。向导里改的内容会直接写回当前方案，关闭向导不丢，也不会自己保存。
- **直连请求登录使用指南**：“登录方式”区域的「使用文档」与向导第一步都可打开。内容涵盖怎么判断自己的门户适不适合直连、怎么用浏览器开发者工具找到登录请求、占位符与凭据变换脚本怎么写（含 Dr.COM / eportal 这类按本机 IP 加密门户的完整示例）、测试结果怎么解读。

### 体验

- **新安装默认启用夜间暂停时段（23:00–06:00）**：宿舍定时断网时段反复重连没有意义，全新配置在这段时间内暂停检测与自动登录。时段起止可在「设置 · 检测」页调整，也可以整体关闭。**已在使用中的配置不受影响**：升级后你原来的暂停时段设置会被完整保留（包括已经关闭的）。
- **新安装不再默认开始检测、也不默认自动切换方案**：此前程序启动就会立刻开始网络检测，单网络环境用户的「自动切换方案」也在后台每 60 秒空转一次。现在两个开关默认都是关闭的——启动后停在待机状态，在控制台点「启动检测」即可开始；需要多网络自动切换的到「方案」页开启「自动切换」。**已在使用中的配置不受影响**：升级后你原来的设置会被完整保留（包括已经开着的自动切换和「启动后执行」）。
- **方案编辑器里的「网络匹配」默认收起**：网关 IP / WiFi 名称这两项只有多网络环境才用得到，平时折叠起来、不再占地方。如果该方案已经配过匹配规则，打开时会自动展开（免得你以为规则丢了）；折叠状态下也会在标题旁显示已配的内容（如「网关 192.168.7.7 · SSID Dorm-9F」）。点标题即可展开或收起。
- **浅色主题文字更清晰**：正文、次级与说明文字整体加深到黑色系（正文纯黑，最浅一档在浅色背景上仍有约 7.9:1 的对比度）。此前次级与说明文字偏灰，在浅色半透明卡片上阅读长段落（协议、字段说明）比较费眼。深色主题不受影响。
- **直连配置界面重做**：渠道选择改为两张说明卡片，直接标出「需要 Python 与浏览器」还是「免 Python 与浏览器」，便于取舍；直连的各个输入按填写顺序编号分组，每组说明这一步该做什么，并附「填入示例」按钮与占位符速查；密码加密脚本默认收起（用不到时不占地方）。
- **测试失败后知道下一步该改哪里**：发送测试请求的结果面板在结论之外新增针对性指引，例如「未命中成功标识」会直接提示去核对成功关键字，并提醒“响应恒为 HTTP 200 的门户必须填写成功与失败关键字，否则密码错误也会被判成成功”；请求报文与响应片段收进折叠区，脚本报错单独高亮。
- **向导不会让你白走几步**：某一步的必填项没填时，「下一步」会禁用并在底部说明原因（例如「请先关闭向导，在上方页面填写账号并保存，再回来继续」），不会等到最后一步才告诉你缺东西。
- **「浏览器任务」下拉不再出现两个等同的选项**：此前首项是「使用内置默认任务」，而列表里又有一个「通用登录」——两者其实是同一个任务，选哪个都一样，容易让人犹豫。现在只保留任务列表本身，其中内置的那条标注为「通用登录（内置默认）」，选中的就是实际会执行的任务。
- **「从云端仓库导入任务」更好用了**：来源选择（GitHub / Gitee / 自定义）从一串按钮改成分段控件，和「加载索引」放在同一行——点它会用哪个来源一看便知；选中来源下方会说明这个来源的特点。还没加载任务时不再是一片空白，而是明确告诉你点哪里开始，并给一个直达仓库的入口；底部提示也跟着状态变（还没选任务 / 已选中可导入）。
- **国内用户下载任务列表时不再干等**：导入任务弹窗里现在会说明每个来源的特点——选 GitHub 时提示「国内访问可能较慢或加载失败，卡住时请改用 Gitee 镜像」，选 Gitee 时则标注推荐国内用户使用。卡住时切换来源即可，不用猜是网络问题还是地址填错了。
- **「外观」页不再显示用不上的「立即保存」**：外观改动是即时生效并存在本机的，此前点「立即保存」只会得到「配置没有变更，无需保存」，与眼前已经生效的改动相矛盾。现在该页不显示保存按钮。

### 修复

- **任务页「分享适配」按钮指向了错误的仓库**：它的用途是「把你适配好的登录任务分享给社区」，但链接指向了程序本体的代码仓库（点进去只有 Rust 源码），而任务实际存放在单独的任务仓库里。现已修正，点它就直达任务仓库，可以提交自己的适配、也能看到别人分享的任务。
- **切换运行模式前的确认框更易读了**：待改动的设置项改为一行一项、左对齐列名右侧列出「旧值 → 新值」，一眼看清每项会变成什么；此前是几行同色同粗细的文字，改动多时不容易核对。
- **方案里「留空使用全局」的说法是错的，已改正**：方案编辑器的账号框此前提示「留空使用全局」，但程序里并没有“全局账号”这回事——账号只存在方案里，留空就是没有账号、无法自动认证。更麻烦的是登录失败时会提示「请在设置页填写账号」，照着去设置页填，改的其实是**当前方案**（可能是另一个方案的账号）。现已改为「留空无法自动认证」，并把填账号的位置统一到「方案」页。
- **方案的 ID 不再让方案「创建后无法再编辑」**：此前方案 ID 里若含下划线（或名称含空格/中文，自动生成的 ID 也会带连字符），新建后该方案就再也保存不了——点保存会提示「方案 ID 只能包含字母、数字和下划线」，而 ID 输入框本身是灰的、改不了。原因是自动生成的 ID 会把下划线转成连字符，而界面校验不认连字符。现已统一（下划线与连字符都接受），这些方案可以正常编辑保存了。
- **「纯净模式」开关不再被静默翻回**：此前关闭纯净模式后，只要在任意设置页点一次「立即保存」，它就会被悄悄恢复为开启——而界面开关仍显示"已关闭"，与实际配置不一致，也没有任何提示。现已修正，开关状态与保存结果始终一致。
- **Engine 异常重启瞬间不再报"服务故障"**：此前引擎崩溃并自动重启的短暂窗口内，点击「开始/停止监测」或「测试网络」会收到 HTTP 500（表现为服务端故障）。现在改为 503 并提示稍后重试，符合实际情况。
- **任务执行失败不再弹绿色"执行完成"**：此前任务实际失败时也会显示成功样式的提示（后端以 HTTP 200 返回，失败信息在响应体内）。现在按真实成败分流：失败以错误样式提示，并优先展示后端给出的失败原因。
- **定时任务不再被并发的登录打断**：此前登录与定时浏览器任务在后台共享同一个执行槽位，登录失败重试时会连带回收 Worker，导致正在进行的定时任务中途失败，且历史里只留下「请求已取消」——看起来像是被主动取消，实际与用户操作无关。现已改为只回收属于本次登录的资源，不影响他人。
- **卸载 OCR 依赖时不再打断正在进行的任务**：此前若有定时任务或登录正在进行，点「卸载 OCR 依赖」会连带把那个任务掐断，而任务历史里只留下「请求已取消」——看起来像是被主动取消，实际与用户操作无关。现在这种情况会直接提示「有任务正在执行，请稍后再试」，等任务结束后再卸载即可。
- **日志面板刷新不再丢实时日志**：此前点过「清空」后再点刷新，刷新期间新到达的实时日志会被整批丢弃，「N 条新消息」提示也一并消失。现已保留。
- **关闭严格登录模式后，界面不再把"确认检测到门户劫持"说成"按链路推断"**：此前关闭「登录严格模式」会把一次明确的劫持检测降级显示为推断结论（置信度从高降为低），排障时无法区分两者；同时会绕过"同一配置只谨慎尝试一次"的节流。现已保留原始结论。
- **后端长时间无响应时，界面能正常报超时**：此前若响应头已返回但响应体卡住，请求会永久挂起（一直转圈、无提示、保存按钮卡住）。现在超时与取消覆盖到完整响应。
- **弹窗里的确认框不再被弹窗本身挡住**：此前在弹窗内发起确认时（如「关于」页点「卸载」后再点「开始清理」），确认框会显示在该弹窗的下层、必须先手动关掉弹窗才点得到确认。现已确保确认框始终显示在最上层，在弹窗内可直接确认或取消，取消只关闭确认框、不会连带关掉当前弹窗。
- **导入任务弹窗里「直接查看仓库」不再点出一屏乱码般的原始文本**：该链接此前指向的是程序读取任务列表用的索引文件地址，点开看到的是原始 JSON 内容而不是仓库页面。现已改为指向仓库主页，可以直接浏览任务仓库。
- **还没加载任务时不再提示"点击左侧任务查看详情"**：列表为空时左侧根本没有任务可点，提示指向了不存在的东西。现在这种情况显示的是核对提示。

## v5.0.0-alpha.10（2026-09-11）

### 网络监测与自动恢复

- 默认仅开启 HTTP 204 门户检测；TCP 与 URL 内容检测改为按需启用的补充手段
- 网络结论新增“等待检测/证据不足”状态，不再把探测关闭、弱证据或互相冲突的结果误报为离线
- 自动监测、手动诊断和登录后验证采用各自独立的行为：手动诊断不会触发登录，暂停期间也可以执行
- 仪表盘现在会说明网络结论的原因，以及系统接下来会保持观察、尝试登录还是等待修复配置

### 安装、Docker 与发布

- 修复 OCR 依赖安装/卸载时命令拼接错误，`ddddocr` 仍然仅在用户启用 OCR 时按需安装
- Python 环境现在会分别验证解释器、Worker 依赖、版本和浏览器；即使电脑已有 Edge/Chrome，也不会再把缺失的 Playwright Python 包误判为可用
- Worker 首次启动失败时会自动修复环境并重试当前操作，修复成功后自动解除熔断；“重新同步”按钮会执行一次真正的完整校验与同步
- 若 uv 管理的底层 Python 已被系统清理，程序会安全重建损坏的虚拟环境；重建失败会保留并恢复原目录，不再反复复用一个看似存在但无法启动的环境
- OCR 偏好独立保存，安装失败后可在后续自动重试；OCR 只准备 Worker 核心，不会额外触发 Chromium 下载，也不会因自身安装失败阻断普通登录
- Docker 构建现在严格验证 Worker、Playwright 和 Chromium，任一缺失都会阻止构建，避免启动后才发现 Worker 无法登录
- Docker 默认改为拉取 GHCR 预构建的 x64/ARM64 多架构镜像，不再要求每台部署机器重复编译 Rust、前端和 Chromium；源码构建仍可通过独立覆盖文件启用
- 发布页会自动读取本文件中对应版本的更新内容；便携包同时附带更新日志、更改日志、已知问题和许可证
