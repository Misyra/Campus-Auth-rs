## 尚未发布（开发中）

> 已合入代码但尚未发版，随下一个版本号一并发布。用户可感知的变化如下。

### 修复

- **「纯净模式」开关不再被静默翻回**：此前关闭纯净模式后，只要在任意设置页点一次「立即保存」，它就会被悄悄恢复为开启——而界面开关仍显示"已关闭"，与实际配置不一致，也没有任何提示。现已修正，开关状态与保存结果始终一致。
- **Engine 异常重启瞬间不再报"服务故障"**：此前引擎崩溃并自动重启的短暂窗口内，点击「开始/停止监测」或「测试网络」会收到 HTTP 500（表现为服务端故障）。现在改为 503 并提示稍后重试，符合实际情况。
- **任务执行失败不再弹绿色"执行完成"**：此前任务实际失败时也会显示成功样式的提示（后端以 HTTP 200 返回，失败信息在响应体内）。现在按真实成败分流：失败以错误样式提示，并优先展示后端给出的失败原因。
- **定时任务不再被并发的登录打断**：此前登录与定时浏览器任务在后台共享同一个执行槽位，登录失败重试时会连带回收 Worker，导致正在进行的定时任务中途失败，且历史里只留下「请求已取消」——看起来像是被主动取消，实际与用户操作无关。现已改为只回收属于本次登录的资源，不影响他人。
- **日志面板刷新不再丢实时日志**：此前点过「清空」后再点刷新，刷新期间新到达的实时日志会被整批丢弃，「N 条新消息」提示也一并消失。现已保留。
- **关闭严格登录模式后，界面不再把"确认检测到门户劫持"说成"按链路推断"**：此前关闭「登录严格模式」会把一次明确的劫持检测降级显示为推断结论（置信度从高降为低），排障时无法区分两者；同时会绕过"同一配置只谨慎尝试一次"的节流。现已保留原始结论。
- **后端长时间无响应时，界面能正常报超时**：此前若响应头已返回但响应体卡住，请求会永久挂起（一直转圈、无提示、保存按钮卡住）。现在超时与取消覆盖到完整响应。

## v5.0.0-alpha.10（2026-09-11）

### 网络监测与自动恢复

- 默认仅开启 HTTP 204 门户检测；TCP 与 URL 内容检测改为按需启用的补充手段
- 网络结论新增“等待检测/证据不足”状态，不再把探测关闭、弱证据或互相冲突的结果误报为离线
- 自动监测、手动诊断和登录后验证采用各自独立的行为：手动诊断不会触发登录，暂停期间也可以执行
- 仪表盘现在会说明网络结论的原因，以及系统接下来会保持观察、尝试登录还是等待修复配置

### 安装、Docker 与发布

- 修复 OCR 依赖安装/卸载时命令拼接错误，`ddddocr` 仍然仅在用户启用 OCR 时按需安装
- Python 环境现在会分别验证解释器、Worker 依赖、版本和浏览器；即使电脑已有 Edge/Chrome，也不会再把缺失的 Playwright Python 包误判为可用
- Worker 首次启动失败时会自动修复环境并重试当前操作，修复成功后自动解除熔断；“重新同步”按钮会执行一次真正的完整校验与同步
- 若 uv 管理的底层 Python 已被系统清理，程序会安全重建损坏的虚拟环境；重建失败会保留并恢复原目录，不再反复复用一个看似存在但无法启动的环境
- OCR 偏好独立保存，安装失败后可在后续自动重试；OCR 只准备 Worker 核心，不会额外触发 Chromium 下载，也不会因自身安装失败阻断普通登录
- Docker 构建现在严格验证 Worker、Playwright 和 Chromium，任一缺失都会阻止构建，避免启动后才发现 Worker 无法登录
- Docker 默认改为拉取 GHCR 预构建的 x64/ARM64 多架构镜像，不再要求每台部署机器重复编译 Rust、前端和 Chromium；源码构建仍可通过独立覆盖文件启用
- 发布页会自动读取本文件中对应版本的更新内容；便携包同时附带更新日志、更改日志、已知问题和许可证
